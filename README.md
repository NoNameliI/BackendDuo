# PostgreSQL Interactive Studio

Десктопный тренажёр по SQL и PostgreSQL для Windows 10–11. Короткая теория с бизнес-кейсом и сразу практика: запросы выполняются в настоящем PostgreSQL прямо внутри приложения, а решение проверяется автоматически.

- **Песочница без установки сервера.** PostgreSQL 18 работает в WebAssembly ([PGlite](https://pglite.dev)) в отдельном потоке. Доступа к файлам и сети у неё нет; для каждого задания база заново создаётся из его `setup`.
- **Пять миров на карте навыков:** реляционная модель и CRUD, фильтрация и агрегация, соединения, продвинутая аналитика, архитектура и оптимизация.
- **Типы заданий:** SQL-тренажёр (выборка и изменение данных), «Собери схему» (визуальный конструктор ERD с генерацией DDL), «Оптимизируй запрос» (проверка по `EXPLAIN`), «Найди баг» (ревью кода), тесты.
- **Онбординг:** путь новичка с визуальной песочницей без кода и путь с опытом — адаптивный вступительный тест, который открывает уже знакомые темы.
- **Геймификация:** XP, уровни от SQL Trainee до Database Architect, серии дней, бейджи.
- **Windows:** сворачивание в трей, напоминание о серии, горячие клавиши, тёмная и светлая темы.

## Запуск

Нужны Node.js 22+ и npm. Для десктопной сборки дополнительно — Rust (toolchain `stable-msvc`), Visual Studio Build Tools с компонентом «Разработка классических приложений на C++» и WebView2 (в Windows 11 уже есть).

```bash
npm install
npm run dev          # веб-версия на http://localhost:1420 — удобно для разработки интерфейса
npm run tauri dev    # десктопное приложение
npm run tauri build  # установщики MSI и NSIS в src-tauri/target/release/bundle
```

Проверки:

```bash
npm run build             # типы и production-сборка
npm test                  # юнит-тесты: движок, проверка решений, геймификация, парсеры
npm run validate:content  # каждое эталонное решение проходит свою проверку, стартовый код — нет
```

## Горячие клавиши

| Клавиши | Действие |
|---|---|
| `Ctrl+Enter` | выполнить запрос |
| `Ctrl+Shift+Enter` | проверить решение |
| `Ctrl+K` | палитра: уроки, задания, разделы, действия |
| `Alt+←` / `Alt+→` | предыдущее / следующее задание |
| `1`–`6` | выбрать вариант ответа в тесте |

## Структура

```
courses/postgres/        учебный курс — только данные
  manifest.json          миры, уроки, порядок, уровни, бейджи, наборы данных
  w1 … w5/*.md           уроки: теория и задания
  datasets/*.sql         общие наборы данных для заданий
  placement.json/.md     вступительный тест
  onboarding.json        сценарий для новичков
  errors.json            подсказки к кодам ошибок PostgreSQL
src/
  engine/                SandboxEngine и его реализация для PostgreSQL (PGlite в Web Worker)
  checker/               проверка решений: result, state, schema, plan, choice, review
  content/               zod-схемы, парсер уроков, загрузчик курса
  progress/              хранимый прогресс и правила геймификации
  features/              экраны: урок, карта, профиль, онбординг, ERD, палитра
  platform/              единственная точка доступа к API оболочки (Tauri) с веб-фолбэками
  ui/                    общие компоненты
src-tauri/               оболочка Tauri 2: окно, трей, уведомления, хранилище
scripts/                 validate-content
```

## Как добавить урок

1. Создайте файл в папке мира, например `courses/postgres/w2/04-case.md`:

   ````markdown
   # CASE и COALESCE

   Короткая теория и бизнес-кейс.

   ## task w2-case-status
   ```json
   {
     "type": "result",
     "title": "Статусы по-русски",
     "dataset": "shop",
     "hints": ["Используйте CASE status WHEN 'new' THEN 'новый' … END."]
   }
   ```
   Условие задания: какие колонки вывести и в каком порядке.

   ```sql solution
   SELECT id, CASE status WHEN 'new' THEN 'новый' ELSE 'в работе' END AS status_ru FROM orders;
   ```
   ````

2. Добавьте урок в `manifest.json` в нужный мир: `{ "id": "w2-case", "file": "w2/04-case.md" }`. По умолчанию урок открывается после предыдущего; другой порядок задаётся полем `requires`.
3. Запустите `npm run validate:content`. Проверка загрузит каждое задание в чистую базу, выполнит эталонное решение через ту же проверку, что и у ученика, и убедится, что стартовый код её не проходит.

Блоки задания: `json` — параметры (тип, XP, подсказки, флаги проверки), `sql setup` — подготовка базы, `sql starter` — код в редакторе при открытии, `sql solution` — эталон, `sql check` — запросы для проверки состояния, `sql query` — запрос для задач на оптимизацию, `<язык> code` — фрагмент кода для ревью. Полная схема — в `src/content/schema.ts`.

## Как будет добавляться новый модуль

Приложение рассчитано на несколько технологий (FastAPI, Python, Redis и т. д.), но сейчас в нём только модуль PostgreSQL. Граница расширения одна — песочница:

1. Реализовать интерфейс `SandboxEngine` из `src/engine/types.ts` (`init`, `reset`, `execute`, `explain`, `introspect`) для новой технологии и зарегистрировать его в `src/engine/index.ts` под новым видом движка.
2. Описать курс в `courses/<модуль>/manifest.json` с полем `engine`, указывающим этот движок, разложить уроки по тому же формату и подключить курс в `src/content/course.ts`.
3. Добавить проверки, специфичные для технологии, рядом с существующими в `src/checker/`.

Карта навыков, прогресс, геймификация, онбординг и плеер уроков работают с курсом как с данными и не зависят от технологии.
