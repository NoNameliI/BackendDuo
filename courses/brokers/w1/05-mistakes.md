# Типичные ошибки при выборе и применении

Команда принесла три проекта: схему обмена сообщениями в RabbitMQ, настройки топика и читателей в Kafka и записку о переходе между брокерами. Во всех трёх есть ошибки, которые встречаются снова и снова. В этом уроке мы соберём их в список, а в заданиях вы найдёте их в чужих решениях. Новых команд здесь нет: всё опирается на предыдущие уроки и на курсы RabbitMQ и Kafka.

### Ошибки с очередью (RabbitMQ)

- **Ошибка:** две службы читают одну очередь, чтобы каждая получила все сообщения. **Верно:** потребители одной очереди делят сообщения, каждое достаётся одному. Каждой службе нужна своя очередь, привязанная к `exchange` (урок 1.2, курс RabbitMQ, урок 2.1).
- **Ошибка:** очередь создана, но не привязана к `exchange`. **Верно:** без привязки копия сообщения в очередь не попадёт, а сообщение без подходящей привязки отбрасывается без ошибки (курс RabbitMQ, уроки 2.1 и 2.4).
- **Ошибка:** автоподтверждение (`auto_ack=true`) для сообщений, которые нельзя терять. **Верно:** при автоподтверждении сообщение считается подтверждённым в момент доставки: если потребитель упал, повторной доставки не будет. Для важных сообщений подтверждают вручную после обработки (курс RabbitMQ, урок 3.1).
- **Ошибка:** ждать, что подтверждённое сообщение можно прочитать позже. **Верно:** повторно оно не доставляется. Для перечитывания нужен журнал.

### Ошибки с журналом (Kafka)

- **Ошибка:** ключ записи выбран не по сущности (случайный идентификатор, номер записи). **Верно:** ключ равен идентификатору сущности, иначе события одного заказа разойдутся по разным разделам и порядок пропадёт (курс Kafka, урок 2.2).
- **Ошибка:** в группе больше читателей, чем разделов. **Верно:** у раздела в группе один читатель, лишние простаивают. Число разделов задаёт предел параллелизма (урок 1.2).
- **Ошибка:** новая группа с `auto.offset.reset=latest`, которой нужна история. **Верно:** для истории ставят `earliest`. Настройка действует только для группы без сохранённой позиции (курс Kafka, урок 1.3).
- **Ошибка:** `--reset-offsets` без `--execute` или для группы с работающими читателями. **Верно:** без `--execute` команда лишь показывает таблицу, а группа должна быть неактивной.
- **Ошибка:** добавить разделы в топик, где важен порядок. **Верно:** ключ может переехать в другой раздел, и порядок через границу не гарантирован (урок 1.3).
- **Ошибка:** считать, что запись «подтверждается» и удаляется, как сообщение в очереди. **Верно:** закоммиченный offset — позиция группы, а не отметка о выполнении. Запись остаётся до конца срока хранения.

### Ошибки при выборе

- **Ошибка:** выбирать по названию, а не по требованиям. **Верно:** сначала вопросы урока 1.1.
- **Ошибка:** переносить привычки одной системы на другую: ждать «подтверждения удаления» от Kafka или перечитывания от очереди. **Верно:** сверяйтесь с таблицей из урока 1.4.
- **Ошибка:** считать, что один брокер обязан закрыть все потоки. **Верно:** поручения и события часто разделяют: письма через очередь, события оплаты в журнал.

### Как искать ошибки в чужой схеме

1. Выпишите, кто читает: одна служба или несколько, и как они делят данные.
2. Найдите, что происходит после обработки: подтверждение, коммит позиции, срок хранения.
3. Проверьте порядок: есть ли ключ, один ли раздел, один ли потребитель.
4. Проверьте историю: нужна ли она и откуда новый читатель начнёт.
5. Найдите настройку, которая противоречит цели строки.

### Шпаргалка

- RabbitMQ: своя очередь на службу, привязка обязательна, `auto_ack=true` теряет сообщения при падении, подтверждённое не вернуть.
- Kafka: ключ по сущности, читателей не больше разделов, `earliest` для истории, `--reset-offsets` с `--execute` и без читателей, рост числа разделов ломает порядок, закоммиченный offset не удаляет записи.
- Выбор: по требованиям, по таблице, при необходимости разделить поток.
