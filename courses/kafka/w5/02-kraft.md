# KRaft

Вы принимаете кластер от предыдущей команды. В инструкции по запуску есть строка с адресом ZooKeeper, а вы планируете перейти на Kafka 4.x. Нужно понять, что из старой инструкции ещё работает, как устроены узлы теперь и сколько из них нужно для надёжного кластера.

Песочница курса не моделирует кворум контроллеров и форматирование хранилища: в ней три брокера, к которым вы обращаетесь через `localhost:9092`. Поэтому урок — теория, а проверка — задания с выбором ответа и разбором. Все факты — из документации Apache Kafka 4.4.

### Что изменилось в 4.0

Apache Kafka 4.0 поддерживает только режим KRaft. Режим с ZooKeeper удалён. Версия 3.9 — последняя, в которой есть переходный режим (bridge). Для вас это значит:

- кластер на ZooKeeper нельзя просто обновить до 4.x: сначала его переводят на KRaft;
- адрес ZooKeeper в конфигурации и командах больше не нужен: в 4.x ZooKeeper нет;
- инструкции и скрипты, написанные для ZooKeeper, нужно перечитать.

### Роли узла

Каждый узел кластера получает роль в настройке `process.roles`.

```text
process.roles=роль[,роль]
```

- `broker` — узел хранит партиции и обслуживает продюсеров и потребителей;
- `controller` — узел входит в кворум контроллеров;
- `broker,controller` — одна и та же машина играет обе роли (combined). Этот вариант подходит только для разработки.

В рабочем кластере брокеры и контроллеры разносят по разным узлам.

### Кворум контроллеров

Контроллеры образуют кворум. Кластер работает, пока живо большинство контроллеров. Размер кворума — 3 или 5.

| Контроллеров | Большинство | Сколько может отказать |
| --- | --- | --- |
| 3 | 2 | 1 |
| 5 | 3 | 2 |

Общее правило: кворум из `2N+1` контроллеров переживает отказ `N`. Чётные размеры (2, 4) не помогают: для четырёх нужно то же большинство из трёх, и выдерживают они один отказ, как и три.

Как узлы узнают о составе кворума:

- **Статически**: `controller.quorum.voters=id@хост:порт,id@хост:порт,…`. Для каждого контроллера указывают числовой `id`, хост и порт.
- **Динамически** (с версии 4.1, `kraft.version=1`): вместо списка участников задают `controller.quorum.bootstrap.servers`.

Пример статического списка для трёх контроллеров:

```text
controller.quorum.voters=1@ctl-1:9093,2@ctl-2:9093,3@ctl-3:9093
```

### Форматирование хранилища

Хранилище нового узла нужно отформатировать явно: автоматического форматирования нет. Порядок такой:

```text
kafka-storage.sh random-uuid
kafka-storage.sh format --cluster-id ИДЕНТИФИКАТОР --standalone --config server.properties
```

- `random-uuid` печатает новый идентификатор кластера;
- `format` готовит хранилище. `--cluster-id` — идентификатор из первой команды, `--config` — файл настроек узла;
- `--standalone` — режим для одного узла, как в быстром старте из документации.

### К какому адресу обращаться

В предыдущих уроках вы всегда указывали `--bootstrap-server localhost:9092`: это адрес **брокера**. Так работают `kafka-topics.sh`, `kafka-console-producer.sh`, `kafka-console-consumer.sh`, `kafka-consumer-groups.sh` и `kafka-configs.sh`.

Для команд про кворум и возможности кластера используется `--bootstrap-controller`: он указывает на контроллер. Это `kafka-metadata-quorum` и `kafka-features describe`. `kafka-configs` принимает его тоже.

В песочнице есть только адрес брокера, поэтому проверьте на нём то, что работает так же, как в настоящем кластере:

```broker example
kafka-topics.sh --bootstrap-server localhost:9092 --create --topic audit-log --partitions 3 --replication-factor 3
kafka-topics.sh --bootstrap-server localhost:9092 --create --topic invoices --partitions 3 --replication-factor 3 --config min.insync.replicas=2
kafka-topics.sh --bootstrap-server localhost:9092 --list
```

```text
Created topic audit-log.
Created topic invoices.
audit-log
invoices
```

Здесь `--bootstrap-server` — единственный адрес, и никакого ZooKeeper в командах нет.

### Частые ошибки

- **Ошибка:** обновлять кластер на ZooKeeper прямо до 4.x. **Верно:** 4.x работает только в KRaft, сначала кластер переводят на KRaft (последний релиз с переходным режимом — 3.9).
- **Ошибка:** ставить контроллеров поровну, например двух или четырёх. **Верно:** 3 или 5. Для четырёх устойчивость не лучше, чем для трёх.
- **Ошибка:** оставить в рабочем кластере `process.roles=broker,controller`. **Верно:** combined подходит только для разработки, роли разносят по узлам.
- **Ошибка:** запускать узел, не отформатировав хранилище. **Верно:** сначала `kafka-storage.sh random-uuid` и `kafka-storage.sh format`, автоформатирования нет.

### Шпаргалка

- 4.0 — только KRaft, ZooKeeper удалён; 3.9 — последний релиз с bridge.
- `process.roles`: `broker`, `controller` или `broker,controller` (только для разработки).
- Кворум: 3 или 5 контроллеров, нужно большинство живых; `2N+1` переживает `N` отказов.
- `controller.quorum.voters=id@хост:порт` — статически; `controller.quorum.bootstrap.servers` — динамически (4.1+, `kraft.version=1`).
- `kafka-storage.sh random-uuid`, затем `kafka-storage.sh format --cluster-id ИД --standalone --config файл`.
- `--bootstrap-server` — брокеры; `--bootstrap-controller` — контроллеры (`kafka-metadata-quorum`, `kafka-features describe`).
