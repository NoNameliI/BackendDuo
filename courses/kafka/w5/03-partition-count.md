# Сколько нужно партиций

Сервис аналитики кликов отстаёт: события приходят быстрее, чем потребители успевают их разобрать. Команда добавила потребителей в группу, а отставание не изменилось. Причина в числе партиций топика. В этом уроке вы научитесь его считать, увеличивать и понимать, что при этом происходит с ключами.

### Партиция — единица параллелизма

Партицию внутри группы читает **один** потребитель. Поэтому потребителей в группе полезно держать не больше, чем партиций: лишние простаивают. Напомним из урока 2.3: группа делит партиции между участниками, а один участник может получить несколько партиций.

Отсюда простое правило: число партиций ограничивает, сколько потребителей группы работают одновременно. Топик из одной партиции читает один потребитель, сколько бы их ни было в группе.

Пример: сценарий с топиком `readings` из четырёх партиций и двумя потребителями. Каждый получает две партиции, и вместе они справляются с потоком датчиков. Блок `scenario example` — это сценарий целиком: топик создаёт `setup`, участники описаны в `actors`, условия — в `expect`.

```scenario example
{
  "sim": "kafka",
  "seed": 1,
  "durationMs": 15000,
  "setup": "kafka-topics.sh --bootstrap-server localhost:9092 --create --topic readings --partitions 4 --replication-factor 3",
  "actors": [
    { "id": "sensors", "kind": "producer", "topic": "readings", "rate": 20, "count": 200, "message": { "key": "sensor-{n%8}", "body": "reading {n}" }, "config": {} },
    { "id": "reader-1", "kind": "consumer", "group": "dashboard", "topics": ["readings"], "processMs": 20, "config": { "auto.offset.reset": "earliest", "auto.commit.interval.ms": 500 } },
    { "id": "reader-2", "kind": "consumer", "group": "dashboard", "topics": ["readings"], "processMs": 20, "config": { "auto.offset.reset": "earliest", "auto.commit.interval.ms": 500 } }
  ],
  "faults": [],
  "expect": [ { "kind": "lagBelow", "group": "dashboard", "value": 30, "byMs": 10000 } ]
}
```

Участники сценария:

- `sensors` — продюсер: 20 записей в секунду, всего 200; ключ `sensor-{n%8}` даёт восемь разных ключей по кругу;
- `reader-1`, `reader-2` — потребители одной группы `dashboard`; `processMs` — сколько миллисекунд занимает обработка одной записи;
- `expect` — условие прохождения. `lagBelow` — отставание группы (сумма по партициям: конец журнала минус закоммиченный offset) не больше `value` после момента `byMs`.

### Как посчитать число партиций

Нужное число партиций — это нагрузка, делённая на скорость одного потребителя, с округлением вверх и запасом.

```text
партиций ≥ записей в секунду ÷ записей в секунду на одного потребителя
```

- Скорость потребителя измеряют: `1000 ÷ время обработки записи в мс`. При `processMs = 60` это около 16 записей в секунду.
- Округляют вверх: 4,8 потребителя — это 5.
- Добавляют запас. Во-первых, нагрузка растёт. Во-вторых, партиции получают неодинаковую долю ключей: часть потребителей работает с перегрузом, остальные простаивают.

Пример: поток 90 записей в секунду, один потребитель обрабатывает 20. Получаем 90 ÷ 20 = 4,5, то есть не меньше 5 партиций, а с запасом — 6–8.

Не берите число «на всякий случай» побольше без расчёта: каждая партиция — отдельный каталог с сегментами и со своими репликами на брокерах (урок 3.1), а уменьшить число партиций нельзя.

### Увеличение числа партиций

Команда:

```text
kafka-topics.sh --bootstrap-server localhost:9092 --alter --topic топик --partitions число
```

Команда знакома по урокам 1.2 и 2.1: `--alter` меняет существующий топик, а число после `--partitions` должно быть **больше** текущего.

При успехе команда ничего не печатает. Попытка уменьшить или оставить как есть заканчивается ошибкой (тексты — так, как их печатает песочница):

```broker example
kafka-topics.sh --bootstrap-server localhost:9092 --create --topic orders --partitions 3 --replication-factor 3
kafka-topics.sh --bootstrap-server localhost:9092 --alter --topic orders --partitions 2
kafka-topics.sh --bootstrap-server localhost:9092 --alter --topic orders --partitions 3
```

```text
Created topic orders.
Error: The topic orders currently has 3 partition(s); 2 would not be an increase.
Error: Topic already has 3 partition(s).
```

Потребители узнают о новых партициях при обновлении метаданных (`metadata.max.age.ms`, по умолчанию 300000 мс, то есть 5 минут), после чего группа ребалансируется. Сроки в песочнице упрощены. Если потребитель настроен с `auto.offset.reset=latest` (по умолчанию), он может пропустить записи, попавшие в новую партицию до того, как он её увидел.

### Ключи и увеличение числа партиций

Запись с ключом попадает в партицию `toPositive(murmur2(ключ)) % число_партиций` (урок 2.1). Число партиций входит в формулу, поэтому после увеличения тот же ключ может попасть в другую партицию. Старые записи остаются где были.

Проверим на топике из трёх партиций. Запишем три записи, увеличим топик до шести и запишем те же ключи ещё раз:

```broker example
kafka-topics.sh --bootstrap-server localhost:9092 --create --topic visits --partitions 3 --replication-factor 3
kafka-console-producer.sh --bootstrap-server localhost:9092 --topic visits --reader-property parse.key=true --reader-property key.separator=: <<EOF
abc:first
hello:first
order-42:first
EOF
kafka-topics.sh --bootstrap-server localhost:9092 --alter --topic visits --partitions 6
kafka-console-producer.sh --bootstrap-server localhost:9092 --topic visits --reader-property parse.key=true --reader-property key.separator=: <<EOF
abc:second
hello:second
order-42:second
EOF
kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic visits --from-beginning --max-messages 6 --formatter-property print.partition=true --formatter-property print.key=true
```

```text
Created topic visits.
Partition:0	abc	first
Partition:0	hello	first
Partition:0	order-42	first
Partition:0	order-42	second
Partition:3	abc	second
Partition:3	hello	second
Processed a total of 6 messages
```

- `print.partition=true` добавляет номер партиции в начало строки, `print.key=true` — ключ;
- ключи `abc` и `hello` до увеличения лежали в партиции 0, а новые записи с теми же ключами ушли в партицию 3;
- ключ `order-42` остался в партиции 0: его хеш при делении на 3 и на 6 даёт 0.

Вывод: порядок событий одного ключа через момент увеличения не гарантирован. Если порядок по ключу важен, число партиций выбирают сразу с запасом, а не наращивают на ходу.

### Частые ошибки

- **Ошибка:** добавлять потребителей в группу, когда топик из одной партиции. **Верно:** сначала увеличьте число партиций: лишние потребители остаются без работы.
- **Ошибка:** пытаться уменьшить число партиций командой `--alter`. **Верно:** уменьшить нельзя, команда вернёт ошибку. Нужен новый топик и перенос данных.
- **Ошибка:** увеличивать партиции топика, где важен порядок по ключу, как будто ничего не происходит. **Верно:** ключ может уйти в другую партицию, порядок через границу не гарантирован.
- **Ошибка:** считать число партиций «по одной на потребителя» без запаса. **Верно:** ключи распределяются неравномерно, нагрузка растёт; берите запас.

### Шпаргалка

- Партицию группы читает один потребитель: потребителей полезно не больше, чем партиций.
- Партиций ≥ нагрузка ÷ скорость потребителя, вверх и с запасом.
- `kafka-topics.sh --bootstrap-server localhost:9092 --alter --topic топик --partitions N` — только увеличение, при успехе тишина.
- Потребители видят новые партиции после `metadata.max.age.ms` (300000 по умолчанию), затем ребаланс.
- После увеличения ключ считается по новому числу: `toPositive(murmur2(ключ)) % N`; порядок по ключу через границу не гарантирован.

```broker setup
kafka-topics.sh --bootstrap-server localhost:9092 --create --topic profiles --partitions 3 --replication-factor 3
```

```broker starter
kafka-topics.sh --bootstrap-server localhost:9092 --alter --topic profiles --partitions …
```

```broker solution
kafka-topics.sh --bootstrap-server localhost:9092 --alter --topic profiles --partitions 6
```

## task kfk-parts-lag

```json
{
  "type": "scenario",
  "title": "Три потребителя, одна партиция",
  "xp": 25,
  "scenario": "w5-partitions",
  "hints": [

    "Шаблон: `kafka-topics.sh --bootstrap-server localhost:9092 --alter --topic … --partitions …`. Три потребителя по 16 записей в секунду справятся с 30 записями в секунду, если у каждого своя партиция."
  ],
  "check": {}
}
```

Сайт (`site`) пишет клики в топик `clicks` со скоростью 30 записей в секунду, ключи `user-0`…`user-19`. Группа `stats` состоит из трёх потребителей, каждый обрабатывает около 16 записей в секунду. В топике одна партиция. Наблюдается: работает один потребитель, отставание растёт. Обещано: к 18-й секунде отставание группы `stats` не больше 60 записей. Исправьте топик. Команды выполняются до начала прогона, поэтому потребители увидят новое число партиций сразу.

```broker starter
kafka-topics.sh --bootstrap-server localhost:9092 --alter --topic clicks --partitions …
```

```broker solution
kafka-topics.sh --bootstrap-server localhost:9092 --alter --topic clicks --partitions 3
```
