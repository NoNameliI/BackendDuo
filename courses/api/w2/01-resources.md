# Ресурсы и адреса

Интернет-магазин электроники открывает API для сайта, мобильного приложения и партнёров. Если каждый разработчик придумывает адреса по-своему — `/getAllProducts`, `/product_info?id=5`, `/deleteItem`, — клиентам приходится заучивать каждый адрес отдельно. **REST** — набор соглашений, по которым адреса и методы выглядят одинаково в тысячах API. Зная их, вы угадаете адрес, ещё не открыв документацию.

В этом мире вы работаете с учебным сервером магазина `https://api.shop.local`. В нём есть категории, товары, покупатели и заказы.

### Что такое REST

REST (Representational State Transfer) — не программа и не протокол, а стиль проектирования API поверх HTTP. Его главная идея:

- всё, с чем работает API, — **ресурсы**: товар, категория, покупатель, заказ;
- у каждого ресурса есть свой **адрес** (путь);
- **что сделать** с ресурсом, говорит **метод** запроса (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`), а не слова в адресе.

Адрес отвечает на вопрос «с чем», метод — на вопрос «что сделать». API, который следует этим правилам, называют **RESTful**.

### Коллекция и отдельный ресурс

Ресурсы одного вида собраны в **коллекцию**. У коллекции свой адрес, у каждого элемента — свой:

```
/коллекция
/коллекция/идентификатор
```

- `/коллекция` — все записи одного вида, например `/products` — все товары.
- `/` — разделитель уровней адреса. Слеш в самом конце (`/products/`) не ставят.
- `идентификатор` — номер (или другой уникальный ключ) одной записи внутри коллекции: `/products/3` — товар с `id` 3.

Запрос к коллекции возвращает список:

```http example
GET /products
```

Сервер ответил `200 OK` и списком из восьми товаров. У каждого есть `id` — по нему товар можно запросить отдельно:

```http example
GET /products/3
```

Теперь в ответе один объект, а не список. Если записи с таким номером нет, сервер отвечает `404 Not Found`:

```http example
GET /products/42
```

### Имена: существительные во множественном числе

Адрес называет ресурс, поэтому в нём **существительные**, а не глаголы. Действие уже выражено методом.

| Так | Не так | Почему |
|---|---|---|
| `GET /products` | `GET /getProducts` | глагол «get» уже сказан методом `GET` |
| `GET /products/3` | `GET /product/3` | коллекция одна и та же, имя всегда во множественном числе |
| `GET /products/3` | `GET /products?id=3` | идентификатор записи — часть пути |
| `DELETE /products/3` | `POST /products/3/delete` | удаление выражает метод `DELETE` |
| `/gift-cards` | `/giftCards`, `/gift_cards` | строчные буквы, слова через дефис |

- Множественное число и для коллекции, и для одной записи: `/products` и `/products/3` — одна коллекция и элемент в ней.
- Параметры после `?` (query) уточняют список: отфильтровать, отсортировать, показать страницу. Им посвящён третий урок мира. Номер одной записи в query не пишут.

Категории магазина — тоже коллекция с таким же устройством:

```http example
GET /categories
```

### Вложенные ресурсы

Некоторые ресурсы принадлежат другим: у покупателя есть заказы, у товара — отзывы. Такую связь показывают **вложенным** адресом:

```
/коллекция/идентификатор/вложенная-коллекция
```

- `/коллекция/идентификатор` — родитель: конкретный покупатель, например `/customers/1`.
- `/вложенная-коллекция` — ресурсы, которые принадлежат этому родителю: `/customers/1/orders` — заказы покупателя 1.
- Вложенная коллекция тоже во множественном числе и тоже существительное.

```http example
GET /customers/1/orders
```

Сервер вернул только заказы покупателя с `id` 1 — у каждого `customer_id` равен 1.

Глубже одного уровня вкладывать не принято. Адрес `/customers/1/orders/6/items/2` трудно читать, а у заказа и так есть собственный адрес в своей коллекции:

```http example
GET /orders/6
```

### CRUD и методы HTTP

С данными делают четыре вещи: создают, читают, изменяют, удаляют. По первым буквам английских слов это называют **CRUD** (Create, Read, Update, Delete). В REST каждому действию соответствует свой метод:

| Действие | Метод и адрес | Успешный ответ |
|---|---|---|
| Create — создать | `POST /коллекция` + тело | `201 Created` и созданная запись |
| Read — прочитать | `GET /коллекция` или `GET /коллекция/идентификатор` | `200 OK` |
| Update — изменить | `PUT` или `PATCH /коллекция/идентификатор` + тело | `200 OK` |
| Delete — удалить | `DELETE /коллекция/идентификатор` | `204 No Content` |

Обратите внимание на адреса:

- **создают** запись в коллекции: `POST /categories`. Номера новой записи клиент ещё не знает — его выдаст сервер;
- **изменяют** и **удаляют** конкретную запись: адрес с идентификатором, `/categories/4`;
- данные новой или изменённой записи передают в теле в формате JSON с заголовком `Content-Type: application/json`.

Добавим категорию «Умные часы»:

```http example
POST /categories
Content-Type: application/json

{"name": "Умные часы", "slug": "watches"}
```

Сервер ответил `201 Created` и вернул запись с новым `id` 4. Поле `slug` — короткое латинское имя категории для адресов сайта. Чем `PUT` отличается от `PATCH`, разберём в следующем уроке, а пока изменим одно поле товара методом `PATCH`:

```http example
PATCH /products/4
Content-Type: application/json

{"stock": 10}
```

Удалим созданную категорию. У `DELETE` тела нет, а сервер отвечает `204 No Content` — успешно, но без тела:

```http example
DELETE /categories/4
```

Повторный запрос этой категории теперь получит `404`:

```http example
GET /categories/4
```

### Частые ошибки

- `GET /product/3` → `GET /products/3`: имя коллекции всегда во множественном числе.
- `POST /createCategory` → `POST /categories`: действие выражает метод, в адресе только ресурс.
- `GET /orders?id=6` → `GET /orders/6`: номер одной записи — часть пути.
- `POST /categories/5` для создания → `POST /categories`: при создании номера ещё нет, его выдаст сервер.

### Шпаргалка

- Коллекция: `/products`. Одна запись: `/products/3`.
- Существительные во множественном числе, строчные буквы, слова через дефис, без слеша в конце.
- Вложенная коллекция: `/customers/1/orders`, не глубже одного уровня.
- `POST /коллекция` — создать (`201`), `GET` — прочитать (`200`), `PUT`/`PATCH /коллекция/id` — изменить (`200`), `DELETE /коллекция/id` — удалить (`204`).
- Тело в JSON — с заголовком `Content-Type: application/json`.


## task rest-nested-orders

```json
{
  "type": "request",
  "title": "Спроектируйте адрес: заказы покупателя",
  "server": "shop",
  "hints": [
    "Раздел «Вложенные ресурсы».",
    "Родитель — конкретный покупатель из коллекции `/customers`. Его заказы — вложенная коллекция `orders`.",
    "`GET /customers/…/…`"
  ]
}
```

В личном кабинете покупателя нужен экран «Мои заказы». Спроектируйте запрос по правилам REST и отправьте его на учебный сервер: прочитать все заказы покупателя с идентификатором `3` как **вложенный ресурс** этого покупателя. Покупатели хранятся в коллекции `customers`, заказы называются `orders`. Параметры после `?` не нужны.

```http starter
GET /customers
```

```http solution
GET /customers/3/orders
```
