# Что такое API и HTTP

Вы открываете приложение доставки, и через секунду на экране список ресторанов. Сами рестораны хранятся не в телефоне, а на сервере компании. Приложение попросило их у сервера и получило ответ. Правила такого разговора и называются **API** (Application Programming Interface — интерфейс для программ). В этом курсе вы научитесь читать и составлять такие запросы, проектировать API и писать первые обработчики на FastAPI.

### Официант и кухня

Удобная аналогия — ресторан. Вы (клиент) не заходите на кухню (сервер), а говорите официанту, что нужно. У официанта есть меню: что можно заказать и как об этом попросить. Меню — это и есть API.

- **Клиент** — тот, кто просит: браузер, мобильное приложение, другая программа.
- **Сервер** — тот, кто отвечает: программа на компьютере компании, у которой есть данные.
- **Запрос** — просьба клиента. **Ответ** — то, что вернул сервер.

Клиент всегда начинает разговор, сервер только отвечает. Один запрос — один ответ.

### HTTP — язык запросов и ответов

Клиент и сервер в вебе договариваются по протоколу **HTTP**. Запрос в HTTP — это просто текст из нескольких частей:

```http
МЕТОД адрес
Заголовок: значение
Заголовок: значение

тело
```

- **Метод** — что сделать: `GET` — получить, `POST` — создать, `PUT` и `PATCH` — изменить, `DELETE` — удалить.
- **Адрес** (URL) — с чем: например, `/restaurants` — список ресторанов.
- **Заголовки** — дополнительные сведения о запросе: в каком формате тело, кто вы, какой ответ вы ждёте.
- Пустая строка отделяет заголовки от **тела**.
- **Тело** — данные, которые вы отправляете. У `GET` тела обычно нет.

Запрос «дай список ресторанов» выглядит так — нажмите «Отправить», и учебный сервер доставки ответит:

```http example
GET /restaurants
Accept: application/json
```

Заголовок `Accept: application/json` говорит: «ответ я жду в формате JSON». Учебный сервер живёт внутри приложения: запрос никуда в интернет не уходит.

### Ответ сервера

Ответ устроен похоже: строка статуса, заголовки, пустая строка, тело.

```http
200 OK
Content-Type: application/json

[{"id": 1, "name": "Пицца у Тони"}, {"id": 2, "name": "Суши-бар"}]
```

- `200` — **код статуса**, `OK` — его название.
- `Content-Type: application/json` — тело ответа в формате JSON.
- Тело — сами данные.

### Коды статусов

Код статуса — трёхзначное число. По первой цифре сразу понятно, чем всё кончилось:

| Группа | Смысл | Примеры |
|---|---|---|
| `2xx` | всё хорошо | `200 OK`, `201 Created` — создано, `204 No Content` — успешно, но без тела |
| `3xx` | ищите в другом месте | `301`, `302` — перенаправление |
| `4xx` | ошибка клиента | `400` — непонятный запрос, `401` — не представились, `404` — не найдено |
| `5xx` | ошибка сервера | `500` — сервер сломался при обработке |

Запомните главное: `4xx` — «исправьте запрос», `5xx` — «проблема не у вас, а на сервере».

Попросите ресторан, которого нет, — сервер ответит `404`:

```http example
GET /restaurants/99
```

### JSON

Данные в API чаще всего передают в формате **JSON**. Он похож на записи из жизни: объект в фигурных скобках, внутри пары «ключ: значение».

```json
{"id": 7, "name": "Маргарита", "price": 450, "vegetarian": true, "tags": ["пицца", "сыр"]}
```

- Ключи и строки — в **двойных** кавычках: `"name"`.
- Числа (`450`) и `true` / `false` пишут без кавычек.
- Пары разделяют запятыми, после последней запятой нет.
- Список — в квадратных скобках: `["пицца", "сыр"]`.

### Части адреса: путь и параметры

Адрес `https://api.food.local/restaurants?city=Казань&page=2` состоит из частей:

- `https://api.food.local` — где находится сервер;
- `/restaurants` — **путь**: какой ресурс нужен;
- после `?` — **параметры запроса** (query) в виде `имя=значение`, разделённые `&`: `city=Казань`, `page=2`.

Путь обычно читается как адрес в каталоге: `/restaurants` — весь список ресторанов, `/restaurants/4` — один ресторан с номером `4`. Номер записи пишут в путь через `/`, а не в параметры.

Параметры уточняют запрос: отфильтровать, отсортировать, показать нужную страницу. Если сервер уже известен, в запросе пишут только путь и параметры. Например, рестораны Москвы, сначала с высоким рейтингом (`sort=-rating`: минус — по убыванию):

```http example
GET /restaurants?city=Москва&sort=-rating
```

### Content-Type и тело запроса

Когда клиент отправляет данные (например, создаёт заказ методом `POST`), он кладёт их в тело и обязательно указывает формат заголовком `Content-Type`:

```http example
POST /orders
Content-Type: application/json

{"restaurant_id": 1, "dish": "Пепперони", "quantity": 1}
```

Сервер ответил `201 Created` и вернул созданный заказ с новым `id`. Без `Content-Type: application/json` сервер может не понять, как читать тело.

Если данные не прошли проверку, сервер отвечает `422` и перечисляет, что не так. Тренажёр переводит этот список на понятный язык:

```http example
POST /orders
Content-Type: application/json

{"restaurant_id": 1, "quantity": 0}
```

### Как работать в тренажёре

Справа вверху — **композер запроса**. Метод выбирается слева от адреса. Вкладка **Params** — параметры запроса таблицей, **Headers** — заголовки, **Body** — тело. На вкладке **Как текст** весь запрос виден целиком в том же формате, что и в этом уроке, и его можно набрать прямо там.

Кнопка «Отправить» отправляет запрос учебному серверу. Ниже, в панели **Ответ**, появятся код статуса и тело ответа, а рядом, в **Ленте запросов**, — строчка про каждый отправленный запрос. Кнопка «Проверить» сравнивает запрос в композере с условием задания.

### Частые ошибки

- `GET /restaurants?city=Казань?page=2` → второй параметр отделяется `&`, а не вторым `?`: `?city=Казань&page=2`.
- `{'dish': 'Суши'}` → в JSON только двойные кавычки: `{"dish": "Суши"}`.
- `POST` с телом без `Content-Type` → добавьте заголовок `Content-Type: application/json`.
- Путать `4xx` и `5xx`: `404` — ошибка в запросе, `500` — сбой сервера.

### Шпаргалка

- Запрос: `МЕТОД адрес`, заголовки `Имя: значение`, пустая строка, тело.
- Методы: `GET` — получить, `POST` — создать, `PUT`/`PATCH` — изменить, `DELETE` — удалить.
- Ответ: код статуса, заголовки, тело. `2xx` — успех, `4xx` — ошибка клиента, `5xx` — ошибка сервера.
- Адрес: путь `/restaurants`, параметры `?city=Казань&page=2`.
- JSON: `{"ключ": "строка", "число": 1, "флаг": true, "список": [1, 2]}`.
- Отправляете JSON — добавьте `Content-Type: application/json`.

```json
{
  "type": "request",
  "title": "Список ресторанов Казани",
  "server": "food",
  "hints": [
    "Разделы «HTTP — язык запросов и ответов» и «Части адреса: путь и параметры».",
    "Нужен метод получения данных, путь `/restaurants` и параметр `city`. Параметр удобно добавить во вкладке Params.",
    "`GET /restaurants?city=…`"
  ]
}
```

Приложению доставки нужен список ресторанов в Казани. Соберите запрос: получить ресурс `/restaurants` с параметром `city`, равным `Казань`.

```http starter
GET /…?city=…
```

```http solution
GET /restaurants?city=Казань
```

{"restaurant_id": 2, "dish": "Филадельфия", "quantity": 2}
