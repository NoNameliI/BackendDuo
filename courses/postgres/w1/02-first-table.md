# Первая таблица

Интернет-магазин «Полка» продаёт книги и канцелярию. Каталог пока живёт в Excel: менеджеры правят один файл, цены записаны то «1 200», то «1200 руб.», а у одного товара вместо цены стоит «уточнить». Реляционная база такого не допустит: у каждого столбца есть **тип**, а у таблицы — **ограничения**. В этом уроке вы создадите таблицы сами и наполните их строками.

### Из чего состоит таблица

**Таблица** — набор строк одинаковой структуры. **Строка** — одна запись, например один товар. **Столбец** описывается тремя частями:

- **имя** — как к нему обращаться: `price`;
- **тип** — какие значения в нём допустимы: `numeric(10, 2)`, то есть число с двумя знаками после точки;
- **ограничения** — дополнительные правила: `NOT NULL` (значение обязательно), `CHECK (price > 0)` и другие.

Столбец также называют колонкой: это слово вы встретите в сообщениях проверки. Все таблицы базы и их столбцы видны на вкладке «Схема».

### CREATE TABLE

`CREATE TABLE` создаёт новую пустую таблицу.

```sql
CREATE TABLE имя_таблицы (
  столбец1 тип ограничения,
  столбец2 тип ограничения,
  столбец3 тип
);
```

- После имени таблицы в круглых скобках перечисляются столбцы, по одному определению на строку.
- Определение столбца: имя, затем тип, затем ограничения через пробел. Ограничения необязательны.
- Определения разделяются запятыми. После последнего запятой нет, сразу закрывающая скобка.
- Имена таблиц и столбцов пишите латиницей, строчными буквами, слова разделяйте `_`: `published_on`.
- В конце — точка с запятой.

Таблица для учебной книжной полки:

```sql example
CREATE TABLE demo_books (
  id           serial PRIMARY KEY,
  title        varchar(200) NOT NULL,
  pages        integer,
  price        numeric(8, 2) NOT NULL CHECK (price > 0),
  in_print     boolean NOT NULL DEFAULT true,
  published_on date
);
```

Результат: таблица `demo_books` создана, строк в ней пока нет. Выровненные пробелами столбцы читать удобнее, но база выравнивания не требует.

### Типы данных

| Тип | Что хранит | Когда использовать | Пример значения |
|---|---|---|---|
| `integer` | целое число (примерно до ±2,1 млрд) | количество, число страниц, ссылка на `id` другой таблицы | `42` |
| `serial` | `integer`, который база заполняет сама: 1, 2, 3… | первичный ключ `id` | не указывают |
| `text` | строка любой длины | имена, названия, e-mail, описания | `'Казань'` |
| `varchar(n)` | строка не длиннее `n` символов | когда предел длины — правило бизнеса: артикул, код | `'A-100'` |
| `numeric(p, s)` | точное десятичное число: всего `p` цифр, из них `s` после точки | деньги, вес | `249.90` |
| `boolean` | истина или ложь | флаги «да/нет»: есть ли на складе | `true`, `false` |
| `date` | дата без времени | день рождения, дата регистрации | `'2024-03-18'` |
| `timestamp` | дата и время | момент оформления заказа | `'2024-03-05 08:50'` |

- `numeric(10, 2)` вмещает числа до 99 999 999.99. Лишние знаки после точки округляются при записи: `12.345` сохранится как `12.35`.
- Для денег берите `numeric`. Типы `real` и `double precision` хранят числа приближённо: в них `0.1 + 0.2` даёт `0.30000000000000004`, и копейки «плывут».
- Для очень больших целых чисел есть `bigint`, но в учебных задачах хватает `integer`.
- `int` — короткое имя того же типа `integer`. В примерах курса встречаются оба написания.
- Текст, даты и время записываются в одинарных кавычках, числа и `true`/`false` — без кавычек.

### Ограничения столбца

Ограничения пишутся после типа, через пробел, в любом порядке. Подробно они разобраны в следующем уроке, здесь — основное:

- `PRIMARY KEY` — первичный ключ: значение уникально и обязательно. Обычно это `id serial PRIMARY KEY`.
- `NOT NULL` — значение обязательно, пустым (`NULL`) столбец быть не может.
- `UNIQUE` — два одинаковых значения в столбце запрещены, например два клиента с одним e-mail.
- `CHECK (условие)` — правило, которое база проверяет при каждой вставке и изменении строки. Условие записывается так же, как в `WHERE`: `CHECK (price > 0)`.
- `DEFAULT значение` — что подставить, если при вставке столбец не указали: `DEFAULT true`, `DEFAULT 0`.

Пример определения столбца с тремя ограничениями: `price numeric(8, 2) NOT NULL CHECK (price > 0)`. Если строка нарушает ограничение, база отклоняет запрос с ошибкой и ничего не сохраняет.

### INSERT: добавление строк

`INSERT INTO` добавляет в таблицу новую строку.

```sql
INSERT INTO таблица (столбец1, столбец2, столбец3)
VALUES (значение1, значение2, значение3);
```

- В первых скобках — столбцы, которые вы заполняете, через запятую.
- После `VALUES` во вторых скобках — значения в том же порядке: первое значение попадёт в первый столбец списка, второе — во второй.
- Значений должно быть ровно столько, сколько столбцов в списке.
- Текст и даты — в одинарных кавычках: `'Улисс'`, `'1922-02-02'`. Числа — без кавычек, с точкой: `320.50`. Логические значения — `true` или `false`.
- Явно пустое значение — слово `NULL` без кавычек.

```sql example
INSERT INTO demo_books (title, pages, price, in_print, published_on)
VALUES ('Сто лет одиночества', 480, 650.00, true, '1967-05-30');
```

Результат: добавлена одна строка.

### Несколько строк за один запрос

Чтобы добавить несколько строк, перечислите после `VALUES` несколько скобок через запятую.

```sql
INSERT INTO таблица (столбец1, столбец2) VALUES
  (значение1, значение2),
  (значение1, значение2),
  (значение1, значение2);
```

- Каждая скобка — одна строка таблицы.
- Скобки разделяются запятыми, после последней скобки — точка с запятой.
- Если хотя бы одна строка нарушит ограничение, не добавится ни одна.

```sql example
INSERT INTO demo_books (title, pages, price, in_print, published_on) VALUES
  ('Маленький принц', 96, 320.5, true, '1943-04-06'),
  ('Улисс', 736, 990, false, '1922-02-02');
```

Результат: добавлено 2 строки. Цены `320.5` и `990` сохранятся как `320.50` и `990.00`: тип столбца `numeric(8, 2)`.

### Пропущенные столбцы: serial и DEFAULT

Столбцы, которых нет в списке `INSERT`, заполняются сами:

- `serial` получает следующий номер: 1, 2, 3… Поэтому `id` в `INSERT` обычно не указывают.
- Столбец с `DEFAULT` получает значение по умолчанию.
- Остальные пропущенные столбцы получают `NULL`. Если у такого столбца есть `NOT NULL`, запрос завершится ошибкой.

```sql
INSERT INTO таблица (обязательный_столбец) VALUES (значение);
```

```sql example
INSERT INTO demo_books (title, price) VALUES ('Справочник без даты', 150);
SELECT * FROM demo_books;
```

| id | title | pages | price | in_print | published_on |
|---|---|---|---|---|---|
| 1 | Сто лет одиночества | 480 | 650.00 | true | 1967-05-30 |
| 2 | Маленький принц | 96 | 320.50 | true | 1943-04-06 |
| 3 | Улисс | 736 | 990.00 | false | 1922-02-02 |
| 4 | Справочник без даты | NULL | 150.00 | true | NULL |

У четвёртой книги `id` выдала база, `in_print` взят из `DEFAULT`, а `pages` и `published_on` остались пустыми.

### Чтение данных: напоминание

Проверить, что лежит в таблице, помогает `SELECT` из прошлого урока: `SELECT столбцы FROM таблица WHERE условие ORDER BY столбец;`. Условия соединяются через `AND` и `OR`, `ORDER BY` по умолчанию сортирует по возрастанию.

Столбец типа `boolean` сам по себе уже условие: `WHERE in_print` означает то же, что `WHERE in_print = true`. Для ложных значений пишите `WHERE in_print = false`.

```sql example
SELECT title, price
FROM demo_books
WHERE in_print
ORDER BY price;
```

| title | price |
|---|---|
| Справочник без даты | 150.00 |
| Маленький принц | 320.50 |
| Сто лет одиночества | 650.00 |

### Связи между таблицами: REFERENCES

Внешний ключ (`FOREIGN KEY`) связывает две таблицы. Столбец одной таблицы хранит `id` строки из другой, а база следит, чтобы такой `id` действительно существовал.

```sql
CREATE TABLE дочерняя_таблица (
  id serial PRIMARY KEY,
  столбец_ссылка integer NOT NULL REFERENCES главная_таблица (id)
);
```

- `REFERENCES главная_таблица (id)` после типа делает столбец внешним ключом.
- Тип ссылки должен совпадать с типом `id`. Для `serial` это `integer`: `serial` — это `integer` с автонумерацией.
- Главную таблицу создают раньше, чем ту, что на неё ссылается.
- Ссылаться можно на столбец с `PRIMARY KEY` или `UNIQUE`.
- `NOT NULL` делает связь обязательной: строка без ссылки не сохранится.

```sql example
CREATE TABLE demo_authors (
  id   serial PRIMARY KEY,
  name text NOT NULL UNIQUE
);
CREATE TABLE demo_poems (
  id        serial PRIMARY KEY,
  title     text NOT NULL,
  author_id integer NOT NULL REFERENCES demo_authors (id)
);
INSERT INTO demo_authors (name) VALUES ('Пушкин'), ('Лермонтов');
INSERT INTO demo_poems (title, author_id) VALUES ('Анчар', 1), ('Парус', 2), ('Пророк', 1);
SELECT * FROM demo_poems;
```

| id | title | author_id |
|---|---|---|
| 1 | Анчар | 1 |
| 2 | Парус | 2 |
| 3 | Пророк | 1 |

Попробуйте вставить стихотворение с `author_id = 99`: автора с таким `id` нет, и база ответит ошибкой `23503` (нарушен внешний ключ).

### Конструктор схемы

В некоторых заданиях вместо редактора открывается конструктор схемы: таблицы собираются мышкой, а SQL пишется сам.

- Кнопка «+ Таблица» добавляет карточку `table_1`. В ней уже есть столбец `id` типа `serial` с первичным ключом.
- Щёлкните по имени таблицы в заголовке карточки и введите своё, например `categories`.
- «+ колонка» внизу карточки добавляет столбец `column_2` типа `text`. Щёлкните по имени и переименуйте его.
- Тип выбирается из списка справа от имени: `serial`, `integer`, `bigint`, `text`, `varchar(100)`, `numeric(10, 2)`, `boolean`, `date`, `timestamp`.
- Переключатели рядом с именем: `PK` — первичный ключ, `NN` — `NOT NULL`, `U` — `UNIQUE`. Включённый переключатель подсвечен.
- Чтобы создать внешний ключ, нажмите `FK` у столбца-ссылки, затем щёлкните подсвеченный столбец другой таблицы, на который нужно сослаться (`PK` или `U` с надписью «выбрать»). Тип ссылки станет `integer` сам. `Esc` отменяет выбор, повторное нажатие `FK` убирает связь.
- `×` удаляет столбец, значок корзины — таблицу.
- Панель «Сгенерированный SQL» показывает `CREATE TABLE`, которые получаются из схемы. Ошибки схемы конструктор выводит внизу. Когда всё готово, нажмите «Проверить».

### Частые ошибки

- `price numeric(10, 2),` перед `)` → `price numeric(10, 2)`. После последнего столбца запятая не нужна, иначе будет синтаксическая ошибка.
- `VALUES ("Улисс", 990)` → `VALUES ('Улисс', 990)`. В двойных кавычках PostgreSQL ищет столбец с таким именем и сообщает, что его нет.
- `VALUES ('Улисс', 990,50)` → `VALUES ('Улисс', 990.50)`. Запятая разделяет значения: база увидит три значения вместо двух.
- `INSERT INTO demo_books VALUES ('Улисс', 990)` → `INSERT INTO demo_books (title, price) VALUES ('Улисс', 990)`. Без списка столбцов значения раскладываются по всем столбцам таблицы по порядку, начиная с `id`: `'Улисс'` попадёт в `id`, и запрос завершится ошибкой.

### Шпаргалка

```sql
CREATE TABLE t (
  id serial PRIMARY KEY,
  name text NOT NULL UNIQUE,
  price numeric(10, 2) NOT NULL CHECK (price > 0),
  active boolean NOT NULL DEFAULT true,
  other_id integer REFERENCES other (id)
);
INSERT INTO t (name, price) VALUES ('текст', 99.90);
INSERT INTO t (name, price, active) VALUES ('a', 10, true), ('b', 20, false);
SELECT name, price FROM t WHERE active AND price < 50 ORDER BY price;
```

## task w1-erd-catalog

Каталог растёт, и товарам нужны категории. Соберите схему в конструкторе:

- `categories`: `id` — первичный ключ; `name` — текст, обязательный и уникальный;
- `products`: `id` — первичный ключ; `name` — текст, обязательный; `price` — `numeric(10, 2)`, обязательная; `category_id` — обязательная ссылка на `categories.id`.

```sql solution
CREATE TABLE categories (
  id serial PRIMARY KEY,
  name text NOT NULL UNIQUE
);
CREATE TABLE products (
  id serial PRIMARY KEY,
  name text NOT NULL,
  price numeric(10, 2) NOT NULL,
  category_id integer NOT NULL REFERENCES categories (id)
);
```
