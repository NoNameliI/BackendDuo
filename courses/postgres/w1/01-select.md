# Чтение данных: SELECT

Менеджеры «Полки» каждый день задают базе вопросы: какие товары дешевле 100 ₽, кто из клиентов живёт в Самаре, что заканчивается на складе. Каждый такой вопрос записывается одним запросом `SELECT`. Он ничего не меняет в базе, только читает данные и показывает результат. Поэтому здесь можно экспериментировать сколько угодно.

Примеры ниже работают на учебной базе магазина. Запускайте их, меняйте условия и запускайте снова: так быстрее всего понять, что делает каждая часть запроса.

### Учебная база «Полки»

Во всех заданиях урока используется одна и та же база из пяти таблиц:

| Таблица | Что хранит | Столбцы |
|---|---|---|
| `categories` | категории товаров | `id`, `name`, `parent_id` |
| `products` | товары | `id`, `name`, `category_id`, `price` (цена), `stock` (остаток на складе, шт.) |
| `customers` | клиенты | `id`, `full_name`, `email`, `city`, `registered_on` (дата регистрации) |
| `orders` | заказы | `id`, `customer_id`, `status` (`new`, `paid`, `shipped`, `cancelled`), `created_at` (дата и время) |
| `order_items` | позиции заказов | `order_id`, `product_id`, `quantity` (количество), `price` |

`NULL` в результате означает «значение не указано»: например, у одного клиента не заполнен город.

### SELECT и FROM

`SELECT` перечисляет столбцы, которые нужно показать, а `FROM` называет таблицу, из которой их взять.

```sql
SELECT столбец1, столбец2 FROM таблица;
```

- После `SELECT` идут имена столбцов через запятую. После последнего столбца запятой нет.
- После `FROM` идёт имя таблицы.
- Столбцы в результате идут в том порядке, в котором вы их перечислили.
- Точка с запятой `;` завершает запрос.
- Ключевые слова можно писать любыми буквами, но принято заглавными: `SELECT`, `FROM`. Переносы строк и лишние пробелы ни на что не влияют, поэтому длинный запрос удобно разбить на строки.

```sql example
SELECT full_name, city FROM customers;
```

| full_name | city |
|---|---|
| Анна Смирнова | Казань |
| Борис Петров | Москва |
| Вера Ким | Казань |
| Глеб Орлов | Самара |
| … | … |

… всего 8 строк.

Звёздочка `*` вместо списка столбцов означает «все столбцы таблицы» в том порядке, в котором их создали:

```sql example
SELECT * FROM categories;
```

| id | name | parent_id |
|---|---|---|
| 1 | Книги | NULL |
| 2 | Канцелярия | NULL |
| 3 | Художественная литература | 1 |
| 4 | Нон-фикшн | 1 |
| 5 | Тетради и блокноты | 2 |
| 6 | Ручки и карандаши | 2 |

`*` удобна, чтобы быстро заглянуть в таблицу. В заданиях перечисляйте столбцы явно: проверка сравнивает и набор столбцов, и их порядок.

### Псевдонимы: AS

`AS` даёт столбцу результата другое имя. Сама таблица при этом не меняется.

```sql
SELECT столбец AS новое_имя FROM таблица;
```

- `AS` и новое имя пишутся сразу после столбца или выражения, до запятой.
- Имя пишите латиницей, строчными буквами, слова разделяйте `_`: `since`, `line_total`. Кавычки не нужны.
- Чаще всего псевдоним дают вычисляемому столбцу (следующий раздел). Без него PostgreSQL назовёт такой столбец `?column?`.

```sql example
SELECT full_name AS customer, registered_on AS since
FROM customers;
```

| customer | since |
|---|---|
| Анна Смирнова | 2023-02-14 |
| Борис Петров | 2023-03-01 |
| Вера Ким | 2023-05-20 |
| … | … |

… всего 8 строк.

### Вычисления в SELECT

Столбец результата не обязан лежать в таблице: его можно вычислить из других столбцов. Выражение считается отдельно для каждой строки.

```sql
SELECT столбец1, столбец1 * столбец2 AS имя FROM таблица;
```

- Арифметика: `+` сложение, `-` вычитание, `*` умножение, `/` деление.
- Умножение и деление выполняются раньше сложения и вычитания, как в школе. Порядок меняют скобками: `(price - 10) * 2`.
- Можно смешивать столбцы и числа: `price * 2`, `stock - 1`.
- Вычисляемому столбцу дайте имя через `AS`.

Сколько стоит каждая позиция заказа — количество, умноженное на цену:

```sql example
SELECT order_id, product_id, quantity, price,
       quantity * price AS line_total
FROM order_items;
```

| order_id | product_id | quantity | price | line_total |
|---|---|---|---|---|
| 1 | 1 | 1 | 590.00 | 590.00 |
| 1 | 7 | 2 | 249.90 | 499.80 |
| 2 | 6 | 1 | 1450.00 | 1450.00 |
| 3 | 4 | 1 | 890.00 | 890.00 |
| 3 | 10 | 5 | 89.00 | 445.00 |
| … | … | … | … | … |

… всего 20 строк.

`SELECT` без `FROM` работает как калькулятор. Обратите внимание: деление двух целых чисел отбрасывает дробную часть. Чтобы получить дробь, запишите хотя бы одно число с точкой.

```sql example
SELECT 7 / 2 AS whole, 7.0 / 2 AS exact, 10 - 3 * 2 AS mixed;
```

| whole | exact | mixed |
|---|---|---|
| 3 | 3.5000000000000000 | 4 |

### WHERE

`WHERE` оставляет в результате только строки, для которых условие верно. Остальные строки отбрасываются.

```sql
SELECT столбец1, столбец2
FROM таблица
WHERE столбец оператор значение;
```

- `WHERE` пишется после `FROM`.
- Условие сравнивает столбец со значением (или с другим столбцом) одним из операторов:

| Оператор | Смысл | Пример |
|---|---|---|
| `=` | равно | `city = 'Казань'` |
| `<>` | не равно (можно писать и `!=`) | `status <> 'cancelled'` |
| `<`, `>` | меньше, больше | `price < 100` |
| `<=`, `>=` | не больше, не меньше | `stock >= 10` |

Как записывать значения:

- текст — в одинарных кавычках: `'Казань'`, `'shipped'`. Регистр букв важен: `'казань'` и `'Казань'` — разные значения;
- числа — без кавычек, дробную часть отделяет точка: `249.90`;
- дата — в одинарных кавычках в формате `'ГГГГ-ММ-ДД'`: `'2024-01-01'`; дата со временем — `'2024-03-05 08:50'`. Даты сравниваются как время: раньше значит меньше.

Отгруженные заказы — текстовое значение в кавычках:

```sql example
SELECT id, customer_id, created_at
FROM orders
WHERE status = 'shipped';
```

| id | customer_id | created_at |
|---|---|---|
| 1 | 1 | 2024-01-15 10:20:00 |
| 2 | 2 | 2024-01-20 18:05:00 |
| 5 | 4 | 2024-02-21 11:00:00 |
| 8 | 3 | 2024-03-12 16:45:00 |
| 11 | 7 | 2024-03-22 12:00:00 |

Товары дешевле 100 ₽ — число без кавычек:

```sql example
SELECT name, price FROM products WHERE price < 100;
```

| name | price |
|---|---|
| Тетрадь 48 листов | 95.00 |
| Ручка гелевая | 89.00 |
| Карандаш | 35.00 |

Клиенты, которые зарегистрировались с 1 января 2024 года, — дата в кавычках:

```sql example
SELECT full_name, registered_on
FROM customers
WHERE registered_on >= '2024-01-01';
```

| full_name | registered_on |
|---|---|
| Егор Новиков | 2024-01-09 |
| Жанна Волкова | 2024-02-02 |
| Захар Морозов | 2024-03-18 |

### AND и OR

Несколько условий соединяют словами `AND` и `OR`.

```sql
WHERE условие1 AND условие2
WHERE условие1 OR условие2
```

- `AND` (и) — строка попадает в результат, если верны оба условия.
- `OR` (или) — если верно хотя бы одно из них.
- Каждое условие пишется целиком: `city = 'Самара' OR city = 'Екатеринбург'`. Запись `city = 'Самара' OR 'Екатеринбург'` не сработает.
- Если в одном `WHERE` встречаются и `AND`, и `OR`, заключайте части в скобки. Подробно об этом — в мире «Фильтрация и агрегация».

Товары дороже 500 ₽, которых на складе больше пяти штук:

```sql example
SELECT name, price, stock
FROM products
WHERE price > 500 AND stock > 5;
```

| name | price | stock |
|---|---|---|
| Мастер и Маргарита | 590.00 | 12 |
| Sapiens | 890.00 | 7 |
| Чистый код | 1450.00 | 9 |
| Ежедневник | 690.00 | 15 |

Клиенты из Самары или Екатеринбурга:

```sql example
SELECT full_name, city
FROM customers
WHERE city = 'Самара' OR city = 'Екатеринбург';
```

| full_name | city |
|---|---|
| Глеб Орлов | Самара |
| Жанна Волкова | Екатеринбург |
| Захар Морозов | Самара |

### ORDER BY

Без `ORDER BY` порядок строк не гарантирован: база выдаёт их так, как ей удобнее. `ORDER BY` сортирует результат.

```sql
SELECT столбцы
FROM таблица
WHERE условие
ORDER BY столбец1 направление, столбец2 направление;
```

- Направление `ASC` — по возрастанию: от меньшего к большему, от «А» к «Я», от ранних дат к поздним. Это направление по умолчанию, слово `ASC` можно не писать.
- Направление `DESC` — по убыванию.
- Несколько столбцов перечисляют через запятую. Сначала строки сортируются по первому столбцу. Строки с одинаковым значением первого столбца сортируются по второму.
- Направление задаётся для каждого столбца отдельно: `ORDER BY category_id, price DESC` — категории по возрастанию, цены внутри категории по убыванию.
- Сортировать можно и по псевдониму: `ORDER BY line_total DESC`.
- Пустые значения (`NULL`) при сортировке по возрастанию оказываются в конце.

Товары от самого дорогого к самому дешёвому:

```sql example
SELECT name, price FROM products ORDER BY price DESC;
```

| name | price |
|---|---|
| Чистый код | 1450.00 |
| Атлант расправил плечи | 1290.00 |
| Sapiens | 890.00 |
| Думай медленно, решай быстро | 760.00 |
| … | … |

… всего 12 строк.

Сортировка по двум столбцам:

```sql example
SELECT name, category_id, price
FROM products
ORDER BY category_id, price DESC;
```

| name | category_id | price |
|---|---|---|
| Атлант расправил плечи | 3 | 1290.00 |
| Мастер и Маргарита | 3 | 590.00 |
| Преступление и наказание | 3 | 450.00 |
| Чистый код | 4 | 1450.00 |
| Sapiens | 4 | 890.00 |
| Думай медленно, решай быстро | 4 | 760.00 |
| … | … | … |

… всего 12 строк.

### LIMIT

`LIMIT` оставляет только первые строки результата.

```sql
SELECT столбцы FROM таблица ORDER BY столбец LIMIT число;
```

- `LIMIT` пишется в самом конце запроса, после `ORDER BY`.
- Число — сколько строк оставить.
- Без `ORDER BY` «первые» строки могут быть любыми. Поэтому `LIMIT` почти всегда идёт вместе с `ORDER BY`.

Три самых первых клиента магазина:

```sql example
SELECT full_name, registered_on
FROM customers
ORDER BY registered_on
LIMIT 3;
```

| full_name | registered_on |
|---|---|
| Анна Смирнова | 2023-02-14 |
| Борис Петров | 2023-03-01 |
| Вера Ким | 2023-05-20 |

### Комментарии

Текст после двух дефисов `--` и до конца строки — комментарий. База его не выполняет. Комментарии помогают объяснить, зачем написан запрос.

```sql example
-- товары, которые заканчиваются: меньше 10 штук, но не ноль
SELECT name, stock
FROM products
WHERE stock < 10 AND stock > 0   -- нулевые остатки не берём
ORDER BY stock;
```

| name | stock |
|---|---|
| Думай медленно, решай быстро | 3 |
| Атлант расправил плечи | 4 |
| Sapiens | 7 |
| Чистый код | 9 |

### Порядок частей запроса

Части запроса всегда идут в одном порядке. Ненужные можно пропустить, но переставлять нельзя.

```sql
SELECT столбцы       -- 1. что показать
FROM таблица         -- 2. откуда взять
WHERE условие        -- 3. какие строки оставить
ORDER BY столбцы     -- 4. как отсортировать
LIMIT число;         -- 5. сколько строк вернуть
```

### Частые ошибки

- `WHERE city = "Казань"` → `WHERE city = 'Казань'`. Текст пишут в одинарных кавычках. Двойные кавычки PostgreSQL понимает как имя столбца и сообщает, что столбца «Казань» не существует.
- `WHERE price < 249,90` → `WHERE price < 249.90`. Дробную часть отделяет точка. Запятая в SQL разделяет значения, и здесь она вызовет синтаксическую ошибку.
- `SELECT name price FROM products` → `SELECT name, price FROM products`. Без запятой второе слово становится псевдонимом: вы получите один столбец с именем `price`, в котором лежат названия товаров.
- `… ORDER BY price WHERE stock > 0` → `… WHERE stock > 0 ORDER BY price`. `WHERE` всегда идёт раньше `ORDER BY`, а `LIMIT` — в самом конце.

### Шпаргалка

```sql
SELECT * FROM таблица;                              -- все столбцы
SELECT a, b FROM таблица;                           -- выбранные столбцы
SELECT a AS имя, a * b AS итог FROM таблица;        -- псевдонимы и вычисления
SELECT a FROM таблица WHERE b = 'текст' AND c >= 10;
SELECT a FROM таблица WHERE b = 1 OR b = 2;
SELECT a FROM таблица WHERE d >= '2024-01-01';      -- дата в кавычках
SELECT a FROM таблица ORDER BY b DESC, c;           -- b по убыванию, затем c
SELECT a FROM таблица ORDER BY b DESC LIMIT 3;      -- первые три
-- комментарий до конца строки
```

Бухгалтер хочет знать, сколько денег «лежит» на складе в каждом товаре.

```sql solution
SELECT name, price * stock AS stock_value
FROM products
WHERE stock > 0;
```
