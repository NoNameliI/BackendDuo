# revert и журнал ссылок

Неделю назад в общую ветку `main` попал коммит с ошибочным баннером. Коллеги уже забрали его к себе и работают поверх. Если убрать коммит через `reset`, их история разойдётся с вашей. Для таких случаев есть `git revert`: он не стирает коммит, а добавляет новый, обратный ему. А если вы сами сделали неудачный `reset --hard` и «потеряли» коммиты, их найдёт `git reflog`.

### git revert — отменить коммит новым коммитом

`git revert` смотрит, что изменил указанный коммит, и делает новый коммит с противоположными изменениями. Строки, которые коммит добавил, удаляются, удалённые возвращаются. Старый коммит остаётся в истории.

```sh
git revert --no-edit коммит
```

- `revert` — создать коммит, отменяющий указанный;
- `коммит` — что отменить: `HEAD`, `HEAD~2`, имя ветки или короткий идентификатор из `git log --oneline`;
- `--no-edit` — взять стандартное сообщение без редактора: `Revert "Сообщение отменённого коммита"`, а в теле — строка `This reverts commit <идентификатор>.`

Настоящий Git без `--no-edit` открывает текстовый редактор, чтобы вы поправили сообщение. В песочнице редактора нет, поэтому пишите `--no-edit` всегда: так команда работает одинаково и здесь, и в настоящем терминале.

Добавим телефон и сразу отменим этот коммит:

```sh example
echo "Звоните: 123-45-67" > phone.txt
git add phone.txt
git commit -m "Добавлен телефон"
git revert --no-edit HEAD
git log --oneline
```

Git печатает `[main …] Revert "Добавлен телефон"` и `delete mode 100644 phone.txt`: новый коммит удалил файл. В истории оба коммита — и «Добавлен телефон», и его отмена.

Отменять можно не только последний коммит. `git revert --no-edit HEAD~2` отменит коммит, который был два шага назад, а всё, что сделано после него, останется.

### revert или reset

Обе команды «отменяют», но по-разному.

- `git reset` переписывает историю: коммиты исчезают из ветки. Подходит для своих коммитов, которые ещё никто не получил.
- `git revert` дописывает историю: появляется новый коммит, старые остаются. Подходит для общей ветки и для всего, что уже отправлено на сервер.

Простое правило: если коммит видел кто-то кроме вас, используйте `revert`.

### Конфликт при revert

Если более поздние коммиты меняли те же строки, Git не сможет отменить изменения сам и остановится с конфликтом:

```sh
error: could not revert 1a2b3c4... Новые цены
hint: After resolving the conflicts, mark them with
hint: "git add/rm <pathspec>", then run
hint: "git revert --continue".
```

Конфликт решается так же, как при слиянии: оставьте нужные строки, удалите маркеры `<<<<<<<`, `=======`, `>>>>>>>`, выполните `git add файл` и затем `git revert --continue`. Передумали — `git revert --abort` вернёт всё как было до команды.

### git reflog — журнал перемещений HEAD

Git записывает каждое перемещение `HEAD`: коммит, переключение ветки, `reset`, `merge`, `revert`. Этот журнал и показывает `git reflog`.

```sh
git reflog
git reflog -n число
```

- `reflog` — журнал ссылок, новые записи сверху;
- `-n число` — показать только последние записи;
- каждая строка: короткий идентификатор, метка `HEAD@{n}` и действие, например `commit: Страница доставки` или `reset: moving to HEAD~3`.

```sh example
git reflog
```

В выводе пять строк, от `HEAD@{0}: revert: Revert "Добавлен телефон"` до `HEAD@{4}: commit (initial): Главная страница`.

Журнал хранится только в вашем репозитории и не отправляется на сервер. Настоящий Git хранит записи около 90 дней, поэтому после ошибки обычно есть время всё вернуть. В песочнице журнал ведётся только для `HEAD`.

### HEAD@{n} — где HEAD был раньше

```sh
HEAD@{n}
```

- `HEAD@{0}` — текущее положение;
- `HEAD@{1}` — где `HEAD` был одно перемещение назад, `HEAD@{2}` — два, и так далее;
- фигурные скобки обязательны; ссылку можно передать любой команде, которая ждёт коммит.

Не путайте с `HEAD~n`. `HEAD~2` — два коммита назад по истории ветки. `HEAD@{2}` — два шага назад по журналу, то есть по вашим действиям.

### Как вернуть «потерянный» коммит

После `reset --hard` коммиты пропадают из ветки, но остаются в репозитории. Найдите в `git reflog` строку с нужным коммитом и верните ветку туда.

```sh
git reset --hard HEAD@{n}
```

Уберём три коммита, посмотрим журнал и вернёмся:

```sh example
git reset --hard HEAD~3
git reflog -n 3
git reset --hard HEAD@{1}
git log --oneline -n 2
```

Верхняя строка журнала — сам `reset: moving to HEAD~3`, под ней `HEAD@{1}` — коммит отмены, где ветка была до сброса. После `git reset --hard HEAD@{1}` история снова полная. В отличие от `ORIG_HEAD`, журнал помнит не одно, а все прошлые положения.

Второй случай — удалённая ветка. Ветку с неслитыми коммитами удаляют командой `git branch -D имя`; Git печатает `Deleted branch имя (was 1a2b3c4)`. Коммиты остались, пропало только имя. Вернуть его можно командой создания ветки с указанием коммита:

```sh
git branch имя HEAD@{n}
```

- `имя` — новая ветка;
- `HEAD@{n}` — коммит, на который она будет указывать; подойдёт и идентификатор из `was …`.

Ищите в журнале строку `checkout: moving from имя to main`: запись прямо под ней — последний коммит удалённой ветки.

```sh example
git switch -c promo
echo "Промокод TEA10" > promo.txt
git add promo.txt
git commit -m "Промокод"
git switch main
git branch -D promo
git reflog -n 3
git branch promo HEAD@{1}
git branch
```

В журнале `HEAD@{0}: checkout: moving from promo to main`, а `HEAD@{1}: commit: Промокод`. После `git branch promo HEAD@{1}` ветка `promo` снова в списке.

### Частые ошибки

- `git reset` для коммита, который уже в общей `main` → у коллег останется старая история. Используйте `git revert --no-edit коммит`.
- `git revert` без указания коммита → Git не знает, что отменять. Последний коммит — `git revert --no-edit HEAD`.
- `HEAD@{1}` вместо `HEAD~1` и наоборот → вы попадёте не туда. Сначала посмотрите `git reflog` и найдите нужную строку.
- Расчёт на `reflog` для незакоммиченных правок → журнал хранит только коммиты. То, что не было закоммичено, после `reset --hard` не вернуть.

### Шпаргалка

- `git revert --no-edit коммит` — новый коммит, отменяющий указанный
- `git revert --continue`, `git revert --abort` — после конфликта
- `git reflog`, `git reflog -n 5` — журнал перемещений HEAD
- `HEAD@{n}` — где HEAD был n шагов назад
- `git reset --hard HEAD@{n}` — вернуть ветку в прошлое положение
- `git branch имя HEAD@{n}` — восстановить удалённую ветку

```sh solution
git reset --hard HEAD@{2}
```

```sh solution
git branch feature/search HEAD@{2}
```
