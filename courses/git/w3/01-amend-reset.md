# Правка коммитов и reset

Вы сделали коммит и сразу заметили опечатку в сообщении. Или забыли добавить файл. Или три коммита подряд называются «правки», и стыдно показывать такую историю коллегам. Пока коммиты есть только у вас, их можно исправить: переписать последний коммит или отодвинуть ветку назад. В этом уроке — `git commit --amend` и `git reset`.

Важное правило на весь урок: переписывайте только свои локальные коммиты, которые ещё никто не получил. Как отменять изменения в общей истории, вы узнаете в следующем уроке.

### git commit --amend — исправить последний коммит

`--amend` заменяет последний коммит новым: с тем же родителем, но с новым сообщением и с текущим содержимым индекса.

```sh
git commit --amend -m "Новое сообщение"
git commit --amend --no-edit
```

- `--amend` — не добавлять новый коммит, а заменить последний;
- `-m "…"` — новое сообщение вместо старого;
- `--no-edit` — оставить старое сообщение; нужен, когда вы только досылаете забытый файл;
- всё, что лежит в индексе, войдёт в исправленный коммит. Поэтому забытый файл сначала добавляют: `git add файл`.

Исправим сообщение только что сделанного коммита:

```sh example
echo "Огурцы, помидоры, укроп" > salad.md
git add salad.md
git commit -m "Салат"
git commit --amend -m "Добавлен рецепт салата"
git log --oneline
```

В истории один коммит «Добавлен рецепт салата», коммита «Салат» больше не видно. В выводе `--amend` есть строка `Date:` — Git сохраняет дату исходного коммита.

Теперь дошлём забытый файл, не меняя сообщение:

```sh example
echo "Заправка: сметана" > dressing.md
git add dressing.md
git commit --amend --no-edit
```

Git печатает `2 files changed`: в коммите теперь оба файла.

Обратите внимание: у исправленного коммита новый идентификатор. `--amend` не правит коммит, а создаёт новый и переставляет на него ветку. Поэтому коммит, который уже отправлен коллегам, так исправлять нельзя: у них останется старая версия.

### HEAD~1 и HEAD~N — предыдущие коммиты

Чтобы сказать Git «два коммита назад», не нужно копировать идентификатор.

```sh
HEAD~1
HEAD~N
```

- `HEAD` — коммит, на котором вы сейчас стоите (обычно последний коммит текущей ветки);
- `~1` — на один коммит назад, к родителю; `HEAD~2` — к родителю родителя;
- вместо `HEAD` можно написать имя ветки: `main~1`.

Такая ссылка подходит любой команде, которая ждёт коммит:

```sh example
git log --oneline HEAD~1
```

`git log` начинает историю не с последнего коммита, а с предыдущего: «Добавлен рецепт борша» и «Описание проекта».

### git reset — передвинуть ветку назад

`git reset` переставляет текущую ветку на указанный коммит. Коммиты после него пропадают из истории ветки. Режим решает, что станет с их изменениями.

```sh
git reset --режим коммит
```

- `коммит` — куда поставить ветку, чаще всего `HEAD~1` или `HEAD~N`;
- `--soft` — изменения убранных коммитов остаются в индексе, готовые к новому коммиту;
- `--mixed` — режим по умолчанию, его можно не писать: изменения остаются в рабочей папке, но вне индекса;
- `--hard` — изменения удаляются: рабочая папка и индекс становятся как в указанном коммите.

Сравните три режима на одном коммите.

`--soft` удобен, чтобы переделать коммит или склеить несколько коммитов в один: уберите их, а затем сделайте один новый коммит.

```sh example
git reset --soft HEAD~1
git status
git commit -m "Добавлен салат с заправкой"
```

После `reset` оба файла в разделе `Changes to be committed`, и новый коммит забирает их сразу. Чтобы склеить три последних коммита, пишут `git reset --soft HEAD~3` и один `git commit -m`.

`--mixed` (просто `git reset коммит`) возвращает изменения в рабочую папку. Так коммит можно разобрать и разложить файлы по разным коммитам.

```sh example
git reset HEAD~1
git status
git add salad.md dressing.md
git commit -m "Салат и заправка"
```

После `reset` новые файлы снова в `Untracked files`, а изменённые были бы в `Changes not staged for commit`.

`--hard` выбрасывает изменения целиком:

```sh example
git reset --hard HEAD~1
ls
```

Git отвечает `HEAD is now at` и называет коммит «Добавлен рецепт борша», а `ls` больше не показывает `salad.md` и `dressing.md`.

### Опасность --hard и ORIG_HEAD

`--hard` перезаписывает рабочую папку без вопросов. Незакоммиченные изменения после него не вернуть: Git их никогда не сохранял. Перед `--hard` всегда смотрите `git status`.

С коммитами проще: они не исчезают сразу. Перед каждым `reset` Git запоминает прежнее положение ветки в специальной ссылке `ORIG_HEAD`.

```sh
git reset --hard ORIG_HEAD
```

- `ORIG_HEAD` — коммит, на котором ветка стояла до последнего `reset` (а также `merge` и `rebase`);
- команда возвращает ветку туда, откуда вы её только что сдвинули.

```sh example
git reset --hard ORIG_HEAD
ls
```

Коммит «Салат и заправка» и оба файла снова на месте. `ORIG_HEAD` помнит только одно, последнее положение. Как найти коммит после нескольких неудачных команд, вы узнаете в следующем уроке.

### git reset файл — убрать файл из индекса

С именем файла `reset` не трогает ветку. Он только убирает изменения файла из индекса, а рабочую папку оставляет как есть.

```sh
git reset файл
```

- `файл` — что убрать из индекса; можно перечислить несколько;
- результат тот же, что у `git restore --staged файл`.

```sh example
echo "Соль по вкусу" >> borscht.md
git add borscht.md
git reset borscht.md
git status
```

Git печатает `Unstaged changes after reset:` и `M	borscht.md`: правка в файле осталась, но в индексе её нет.

### Частые ошибки

- `git commit --amend` без `-m` и без `--no-edit` → в песочнице это ошибка, редактора нет. Пишите `--amend -m "…"` или `--amend --no-edit`.
- `--amend` забытого файла без `git add` → файл не попадёт в коммит: `--amend` берёт содержимое индекса.
- `git reset --hard` «чтобы отменить коммит», когда нужны его изменения → они пропадут из рабочей папки. Чтобы сохранить их, используйте `--soft` или `--mixed`.
- `--amend` и `reset` для коммитов, которые уже у коллег → истории разойдутся. Для общих коммитов есть `git revert` (следующий урок).

### Шпаргалка

- `git commit --amend -m "Сообщение"` — заменить последний коммит с новым сообщением
- `git commit --amend --no-edit` — дослать в последний коммит то, что в индексе
- `HEAD~1`, `HEAD~N`, `main~1` — предыдущие коммиты
- `git reset --soft HEAD~N` — убрать N коммитов, изменения в индексе
- `git reset HEAD~N` (`--mixed`) — убрать N коммитов, изменения в рабочей папке
- `git reset --hard HEAD~N` — убрать N коммитов вместе с изменениями
- `git reset --hard ORIG_HEAD` — вернуться туда, где ветка была до `reset`
- `git reset файл` — убрать файл из индекса

Добавьте `contacts.css` в последний коммит. Сообщение коммита должно остаться прежним — **Добавлена страница контактов**, — и новых коммитов появиться не должно.

```sh setup
mkdir site
cd site
git init -q
echo "<h1>Главная</h1>" > index.html
git add index.html
git commit -q -m "Главная страница"
echo "<h1>Контакты</h1>" > contacts.html
echo "h1 { color: navy; }" > contacts.css
git add contacts.html
git commit -q -m "Добавлена страница контактов"
```

```sh solution
git add contacts.css
git commit --amend --no-edit
```

В репозитории `~/blog` последний коммит «Второй пост и правки» смешал две задачи: добавил новый файл `post2.md` и исправил `post1.md`.

Уберите этот коммит из истории, но сохраните все его изменения: правка `post1.md` должна остаться в рабочей папке вне индекса, а `post2.md` — стать неотслеживаемым. Новые коммиты делать не нужно.

```sh setup
mkdir blog
cd blog
git init -q
echo "Первый пост" > post1.md
git add post1.md
git commit -q -m "Первый пост"
echo "Первый пост, исправленный" > post1.md
echo "Второй пост" > post2.md
git add post1.md post2.md
git commit -q -m "Второй пост и правки"
```

```sh solution
git reset HEAD~1
```

```json
    "git reset --soft HEAD~…, затем git commit -m \"…\"."

```

В репозитории `~/shop` после коммита «Каталог товаров» идут три мелких коммита: «Форма заказа: разметка», «Форма заказа: стили» и «Форма заказа: проверка полей».

Замените эти три коммита одним коммитом **Добавлена форма заказа** с теми же изменениями. В итоге в ветке `main` должно быть два коммита: «Каталог товаров» и «Добавлена форма заказа».

```sh setup
mkdir shop
cd shop
git init -q
echo "<ul><li>Чайник</li></ul>" > catalog.html
git add catalog.html
git commit -q -m "Каталог товаров"
echo "<form></form>" > order.html
git add order.html
git commit -q -m "Форма заказа: разметка"
echo "form { margin: 0 auto; }" > order.css
git add order.css
git commit -q -m "Форма заказа: стили"
echo "<form required></form>" > order.html
git add order.html
git commit -q -m "Форма заказа: проверка полей"
```

```sh solution
git reset --soft HEAD~3
git commit -m "Добавлена форма заказа"
```
