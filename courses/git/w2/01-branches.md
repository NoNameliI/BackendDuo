# Ветки

Вы добавляете на сайт новый раздел, а работа растянется на несколько дней. Тем временем в основной версии нашли опечатку, и её нужно исправить прямо сейчас. Если всё делать в одной линии коммитов, недоделанный раздел смешается с исправлением. **Ветки** решают эту задачу: каждая работа идёт в своей ветке и не мешает остальным.

В этом уроке вы научитесь создавать ветки, переключаться между ними, смотреть историю всех веток сразу и удалять ненужные. Сливать ветки вы будете в следующем уроке.

### Что такое ветка и HEAD

Коммиты в Git связаны цепочкой: каждый помнит своего «родителя» — предыдущий коммит. **Ветка** — это просто подвижная метка с именем, которая указывает на один коммит. Когда вы делаете коммит, метка текущей ветки сама сдвигается на новый коммит.

**HEAD** — указатель «вы здесь». Обычно он указывает на ветку, а ветка — на коммит. Новый коммит всегда добавляется туда, куда указывает HEAD.

- Приглашение терминала показывает текущую ветку в скобках: `~/menu (main) $`.
- `git log --oneline` подписывает коммиты метками: `(HEAD -> main)` значит «HEAD указывает на ветку `main`, а она — на этот коммит».
- Вкладка «Граф» справа рисует те же метки: `HEAD → main`.

Ветка в Git очень дешёвая: это одна запись с идентификатором коммита. Копии файлов при этом не создаются.

```sh example
git log --oneline
```

В меню два коммита, и оба на ветке `main`; HEAD указывает на `main`.

### git branch — список веток и новая ветка

```sh
git branch
git branch имя-ветки
```

- `git branch` без аргументов — список веток; звёздочка `*` отмечает текущую;
- `git branch имя-ветки` — создать ветку, которая указывает на тот же коммит, что и HEAD;
- имя — латиница, цифры, дефисы и `/`, без пробелов: `drinks`, `fix-typo`, `feature/search`.

Важно: `git branch имя` только создаёт метку. Вы остаётесь на прежней ветке.

```sh example
git branch
git branch drinks
git branch
```

Первая команда печатает `* main`. После создания ветки в списке две строки: `  drinks` и `* main` — звёздочка всё ещё у `main`.

### git switch — перейти на ветку

```sh
git switch имя-ветки
```

- `switch` — переключиться: HEAD начинает указывать на другую ветку;
- `имя-ветки` — существующая ветка.

При переключении Git меняет файлы рабочей папки так, чтобы они совпадали с последним коммитом выбранной ветки. Новые коммиты теперь будут попадать в эту ветку.

```sh example
git switch drinks
echo "Морс" > drinks.txt
git add drinks.txt
git commit -m "Раздел напитков"
git switch main
ls
```

Git отвечает `Switched to branch 'drinks'`, коммит записывается в ветку `drinks`. После возврата на `main` команда `ls` показывает только `salads.txt` и `soups.txt`: файла `drinks.txt` в ветке `main` нет. Он не пропал — он живёт в ветке `drinks` и вернётся, когда вы на неё переключитесь.

В старых инструкциях вместо `git switch` встречается `git checkout имя-ветки`. Для веток это то же самое, но `switch` понятнее, и в курсе мы используем его.

### git switch -c и git switch - — создать и вернуться

```sh
git switch -c имя-ветки
git switch -
```

- `-c` (create) — создать ветку и сразу перейти на неё; заменяет пару команд `git branch имя` и `git switch имя`;
- `-` (дефис) — вернуться на ветку, где вы были до последнего переключения, как кнопка «назад».

```sh example
git switch -c breakfast
git switch -
```

Первая команда печатает `Switched to a new branch 'breakfast'`, вторая — `Switched to branch 'main'`.

### git log --oneline --graph --all — история всех веток

```sh
git log --oneline --graph --all
```

- `--oneline` — коммит одной строкой (вы знаете его по первому миру);
- `--graph` — слева рисуется граф: `*` — коммит, линии `|`, `/`, `\` — связи с родителями;
- `--all` — показать все ветки, а не только текущую. Без `--all` коммиты других веток не видны.

```sh example
git log --oneline --graph --all
```

Результат:

```
* 98737a5 (drinks) Раздел напитков
* 94eda74 (HEAD -> main, breakfast) Раздел салатов
* d80877c Раздел супов
```

Ветка `drinks` ушла на один коммит вперёд, а `main` и `breakfast` указывают на один и тот же коммит. Вкладка «Граф» показывает то же самое и обновляется после каждой команды: держите её открытой, пока работаете с ветками.

### git branch -v — ветки и их последние коммиты

```sh
git branch -v
```

- `-v` (verbose, «подробно») — для каждой ветки показать короткий идентификатор и сообщение коммита, на который она указывает.

```sh example
git branch -v
```

Видно, что `breakfast` и `main` стоят на коммите «Раздел салатов», а `drinks` — на «Раздел напитков».

### git branch -d и -D — удалить ветку

```sh
git branch -d имя-ветки
git branch -D имя-ветки
```

- `-d` (delete) — удалить ветку, если все её коммиты уже есть в текущей ветке. Иначе Git откажется: `error: the branch '…' is not fully merged`;
- `-D` — удалить принудительно, даже если коммиты ветки больше нигде не сохранены. Такие коммиты пропадут из истории веток — используйте `-D`, только когда работа точно не нужна;
- удалить ветку, на которой вы сейчас стоите, нельзя: сначала переключитесь на другую.

Удаляется только метка. Коммиты, которые есть в других ветках, остаются на месте.

```sh example
git branch -d breakfast
git branch -D drinks
```

Обе команды печатают `Deleted branch … (was …)`. Для `drinks` понадобился `-D`: её коммит «Раздел напитков» не входит в `main`.

### Частые ошибки

- `git branch report` и сразу коммит → коммит попадёт в `main`, ведь `git branch` не переключает. Создавайте и переходите одной командой: `git switch -c report`.
- `git switch имя` для несуществующей ветки → `fatal: invalid reference`. Создайте ветку: `git switch -c имя`.
- Переключение с несохранёнными правками в тех же файлах → Git откажется (`would be overwritten by checkout`). Сначала сделайте коммит.
- `git branch -d` для ветки, на которой вы стоите → ошибка `cannot delete branch`. Переключитесь на `main` и повторите.
- `git log --oneline` «не видит» коммиты другой ветки → добавьте `--all`.

### Шпаргалка

- `git branch` — список веток, `*` — текущая
- `git branch имя` — создать ветку (без перехода)
- `git switch имя` — перейти на ветку; `git switch -` — вернуться на предыдущую
- `git switch -c имя` — создать ветку и перейти на неё
- `git branch -v` — ветки с последними коммитами
- `git log --oneline --graph --all` — граф всех веток; вкладка «Граф» — то же наглядно
- `git branch -d имя` — удалить слитую ветку; `git branch -D имя` — удалить принудительно

1. Создайте ветку `contacts` и перейдите на неё.
2. Создайте файл `contacts.html` с одной строкой `Телефон: 123-45-67`.
3. Закоммитьте его с сообщением **Страница контактов**.

mkdir site
cd site
git init -q
echo "Добро пожаловать" > index.html
git add index.html
git commit -q -m "Главная страница"
```

git switch -c contacts
echo "Телефон: 123-45-67" > contacts.html
git add contacts.html
git commit -m "Страница контактов"
git switch main
```

В репозитории `~/app` три ветки. Посмотрите их командой `git branch -v`:

- `main` — основная ветка;
- `old-header` — старая ветка, все её коммиты уже есть в `main`;
- `experiment` — неудачный эксперимент с тёмной темой; вы сейчас на этой ветке, и её работа больше не нужна.

Удалите ветки `old-header` и `experiment`. В конце вы должны оказаться на ветке `main`, сама `main` не меняется.

```sh setup
mkdir app
cd app
git init -q
echo "Магазин" > index.html
git add index.html
git commit -q -m "Главная страница"
git branch old-header
echo "Каталог товаров" > catalog.html
git add catalog.html
git commit -q -m "Каталог"
git switch -q -c experiment
echo "body { background: black; }" > theme.css
git add theme.css
git commit -q -m "Тёмная тема"
```

```sh solution
git switch main
git branch -d old-header
git branch -D experiment
```
