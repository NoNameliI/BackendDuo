# Первый репозиторий

Вы правите сайт и вдруг понимаете, что вчерашняя версия была лучше, а сохранить её вы не догадались. Git решает эту проблему: он запоминает снимки проекта — **коммиты** — и позволяет в любой момент посмотреть, что и когда менялось, и вернуться назад. В этом уроке вы создадите репозиторий, сделаете первый коммит и научитесь смотреть историю.

Все команды выполняются в учебной песочнице: справа терминал, файлы и граф коммитов. Это модель Git внутри приложения — ваши настоящие файлы она не трогает.

### Терминал и папки

Команды набираются в терминале и выполняются клавишей Enter. Строка перед курсором — **приглашение**: `~/notes $` значит, что вы в папке `notes` внутри домашней папки (`~`). Когда папка станет репозиторием, в скобках появится ветка: `~/notes (main) $`.

Шаблон перехода в папку:

```sh
cd имя-папки
```

- `cd` — сменить текущую папку;
- `имя-папки` — куда перейти; `cd ..` — на уровень выше, `cd ~` — в домашнюю папку.

Ещё три команды оболочки пригодятся с первого дня: `pwd` печатает текущую папку, `ls` — список файлов, `cat файл` — содержимое файла. Файл можно создать командой `echo "текст" > файл`: знак `>` записывает вывод `echo` в файл.

```sh example
mkdir demo
cd demo
echo "Купить хлеб" > shopping.txt
ls
cat shopping.txt
```

### git init — создать репозиторий

Обычная папка становится репозиторием, когда Git заводит в ней служебную папку `.git` — там хранится вся история.

```sh
git init
```

- `git` — сама программа;
- `init` — команда «создать репозиторий в текущей папке».

Git отвечает строкой `Initialized empty Git repository in …/.git/`. Первая ветка в песочнице называется `main` — так её называют GitHub и GitLab. Настоящий Git без настройки называет её `master`; чтобы было как здесь, достаточно один раз выполнить `git config --global init.defaultBranch main`.

```sh example
git init
```

### git status — что изменилось

`git status` показывает состояние файлов. Это самая частая команда Git: выполняйте её до и после каждого действия.

```sh
git status
```

В выводе встречаются три раздела:

- `Untracked files` — новые файлы, за которыми Git пока не следит;
- `Changes to be committed` — изменения, которые войдут в следующий коммит (они в **индексе**);
- `Changes not staged for commit` — изменённые файлы, которые ещё не добавлены в индекс.

```sh example
git status
```

### Три зоны Git

Git различает три места, где живут изменения:

1. **Рабочая папка** — файлы, которые вы видите и правите.
2. **Индекс** (staging area) — «корзина» для следующего коммита: туда вы кладёте только то, что хотите сохранить.
3. **Репозиторий** — сохранённые коммиты.

Путь изменения всегда один: рабочая папка → `git add` → индекс → `git commit` → репозиторий. Вкладка «Статус» справа показывает эти три зоны.

### git add — положить изменения в индекс

```sh
git add файл
```

- `add` — добавить в индекс;
- `файл` — имя файла; можно перечислить несколько через пробел. `git add .` добавляет все изменения в текущей папке — удобно, но легко захватить лишнее.

```sh example
git add shopping.txt
git status
```

Теперь `shopping.txt` в разделе `Changes to be committed`.

### git commit — сохранить снимок

```sh
git commit -m "Сообщение"
```

- `commit` — записать содержимое индекса как новый коммит;
- `-m` — сообщение коммита прямо в команде; кавычки обязательны, если в сообщении есть пробелы;
- сообщение отвечает на вопрос «что сделано»: «Добавлен список покупок», а не «правки».

В песочнице нет текстового редактора, поэтому `-m` нужен всегда.

```sh example
git commit -m "Добавлен список покупок"
```

Git печатает ветку, короткий идентификатор коммита и итог: сколько файлов и строк изменено. Идентификатор — 40 шестнадцатеричных символов; обычно хватает первых семи.

### git log — история

```sh
git log
git log --oneline
```

- `log` — список коммитов, новые сверху: идентификатор, автор, дата, сообщение;
- `--oneline` — каждый коммит одной строкой: короткий идентификатор и сообщение.

```sh example
echo "Купить молоко" >> shopping.txt
git add shopping.txt
git commit -m "Добавлено молоко"
git log --oneline
```

Знак `>>` дописывает строку в конец файла, а `>` перезаписал бы файл целиком.

### Частые ошибки

- `git commit` без `-m` → в песочнице это ошибка. Пишите `git commit -m "Что сделано"`.
- Коммит без `git add` → Git ответит `nothing added to commit`: индекс пуст. Сначала `git add файл`.
- `git init` не в той папке → проверьте `pwd` и при необходимости перейдите командой `cd`.
- `git add .` «на всякий случай» → в коммит попадают черновики. Добавляйте файлы по имени, если сомневаетесь.

### Шпаргалка

- `pwd`, `ls`, `cd папка`, `cat файл`, `echo "текст" > файл` (перезаписать), `>>` (дописать)
- `git init` — создать репозиторий
- `git status` — что изменилось и что в индексе
- `git add файл` — положить изменения в индекс
- `git commit -m "Сообщение"` — сохранить коммит
- `git log`, `git log --oneline` — история

```sh setup
mkdir site
cd site
git init -q
echo "<h1>Мой сайт</h1>" > index.html
git add index.html
git commit -q -m "Главная страница"
echo "# Мой сайт" > README.md
echo "идеи: блог, галерея" > draft.txt
```

```sh solution
git add README.md
```
