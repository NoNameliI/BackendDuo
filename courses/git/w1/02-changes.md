# Смотрим изменения

Вы вернулись к проекту после обеда и не помните, что успели поменять. Или коллега просит проверить его правку перед коммитом. `git status` скажет только, какие файлы изменены. Чтобы увидеть сами строки, нужны `git diff` и `git show`. В этом уроке вы научитесь править файлы в песочнице, читать вывод `diff` и смотреть, что изменил любой коммит.

### Как править файлы в песочнице

Файл можно изменить двумя способами.

**Через редактор.** Справа есть панель «Файлы»: щёлкните по файлу, и он откроется во вкладке «Редактор». Исправьте текст и нажмите Ctrl+S или кнопку «Сохранить». Пока файл не сохранён, рядом с его именем горит пометка «не сохранено». Git видит только сохранённую версию.

**Через терминал.** Команда `echo` из прошлого урока дописывает строку в конец файла:

```sh
echo "текст" >> файл
```

- `echo "текст"` — печатает текст;
- `>>` — дописывает напечатанное в конец файла, не трогая остальное;
- `файл` — куда дописать; если файла нет, он будет создан.

Один знак `>` перезаписывает файл целиком. Так можно собрать файл заново строка за строкой: первая строка через `>`, остальные через `>>`.

```sh example
cd ~
mkdir recipes
cd recipes
git init
echo "Мука — 200 г" > pancakes.txt
echo "Молоко — 300 мл" >> pancakes.txt
echo "Яйца — 2 шт" >> pancakes.txt
git add pancakes.txt
git commit -m "Рецепт блинов"
cat pancakes.txt
```

Получился репозиторий `recipes` с одним коммитом: в `pancakes.txt` три строки.

### git diff — что изменилось в рабочей папке

`git diff` построчно сравнивает рабочую папку с индексом. Проще говоря, показывает правки, которые вы ещё не добавили командой `git add`.

```sh
git diff
git diff файл
```

- `diff` — показать разницу;
- `файл` — необязательно: ограничить вывод одним файлом.

Новые неотслеживаемые файлы в `git diff` не попадают: Git ещё не знает их прежнюю версию. Если вывод пустой, значит, все правки уже в индексе или правок нет.

Пересоберём рецепт: больше муки и новая строка с сахаром. В редакторе вы бы просто поправили одну строку и дописали другую.

```sh example
echo "Мука — 250 г" > pancakes.txt
echo "Молоко — 300 мл" >> pancakes.txt
echo "Яйца — 2 шт" >> pancakes.txt
echo "Сахар — 1 ст. л." >> pancakes.txt
git diff
```

Вывод:

```text
diff --git a/pancakes.txt b/pancakes.txt
index 6230bac..c1224d9 100644
--- a/pancakes.txt
+++ b/pancakes.txt
@@ -1,3 +1,4 @@
-Мука — 200 г
+Мука — 250 г
 Молоко — 300 мл
 Яйца — 2 шт
+Сахар — 1 ст. л.
```

### Как читать diff

Вывод `diff` состоит из заголовка и **фрагментов** (hunks) — кусков файла вокруг изменений.

- `diff --git a/pancakes.txt b/pancakes.txt` — какой файл сравнивается: `a/` — старая версия, `b/` — новая;
- `index 6230bac..c1224d9` — короткие идентификаторы старого и нового содержимого; `100644` — обычный файл;
- `--- a/…` и `+++ b/…` — условные обозначения: строки старой версии помечены `-`, новой — `+`;
- `@@ -1,3 +1,4 @@` — заголовок фрагмента: в старой версии он начинается с 1-й строки и занимает 3 строки, в новой — с 1-й строки и занимает 4;
- строка с `-` в начале удалена, строка с `+` добавлена;
- строка с пробелом в начале не менялась — это **контекст**, он помогает найти место правки.

Изменённая строка выглядит как пара: старый вариант с `-` и новый с `+`. Так и вышло с мукой: `-Мука — 200 г`, затем `+Мука — 250 г`. Строка с сахаром новая, поэтому у неё только `+`.

### git diff --staged — что войдёт в коммит

После `git add` изменения уходят в индекс, и обычный `git diff` их больше не показывает. Чтобы проверить, что именно попадёт в коммит, сравните индекс с последним коммитом.

```sh
git diff --staged
```

- `--staged` — сравнить индекс с последним коммитом, а не рабочую папку с индексом.

Полезная привычка: перед каждым `git commit` выполнять `git diff --staged`.

```sh example
git add pancakes.txt
git diff
git diff --staged
```

Первый `git diff` ничего не печатает: всё уже в индексе. `git diff --staged` выводит тот же фрагмент, что вы видели выше.

### git diff --stat — краткая сводка

Когда изменённых файлов много, полный diff длинный. Флаг `--stat` печатает только сводку: какие файлы изменены и сколько строк добавлено и удалено.

```sh
git diff --stat
git diff --staged --stat
```

- `--stat` — вместо строк показать по строке на файл и итог;
- флаги можно сочетать: `--staged --stat` — сводка по индексу.

```sh example
echo "Соль — щепотка" >> pancakes.txt
git diff --stat
git diff --staged --stat
```

Вывод:

```text
 pancakes.txt | 1 +
 1 file changed, 1 insertion(+)
 pancakes.txt | 3 ++-
 1 file changed, 2 insertions(+), 1 deletion(-)
```

Первая сводка — правка с солью, она пока не в индексе. Вторая — то, что уже в индексе: две добавленные строки и одна удалённая. Изменённая строка с мукой считается как одна удалённая и одна добавленная.

### git log -n — последние коммиты

В большом проекте `git log` выводит сотни коммитов. Флаг `-n` ограничивает их число.

```sh
git log -n число
git log --oneline -n число
```

- `-n число` — показать только столько последних коммитов;
- `--oneline` — как в прошлом уроке: коммит одной строкой.

```sh example
git add pancakes.txt
git commit -m "Тесто послаще"
git log --oneline -n 1
```

Git печатает одну строку: идентификатор, пометку `(HEAD -> main)` и сообщение `Тесто послаще`. **HEAD** — указатель на коммит, в котором вы сейчас находитесь, обычно это последний коммит текущей ветки.

### git show — что изменил коммит

`git log` показывает только сообщения. Чтобы увидеть сами правки коммита, используйте `git show`.

```sh
git show
git show коммит
git show коммит --stat
```

- без аргумента — последний коммит (HEAD);
- `коммит` — идентификатор из `git log --oneline` (хватит первых семи символов) или `HEAD~1` — коммит перед последним, `HEAD~2` — ещё на один раньше;
- `--stat` — вместо строк только сводка, как у `git diff --stat`.

Сначала Git печатает заголовок коммита (идентификатор, автор, дата, сообщение), затем diff в том же формате, что вы уже умеете читать.

```sh example
git show
git show HEAD~1 --stat
```

Первая команда покажет коммит «Тесто послаще»: мука `-200 г` / `+250 г`, добавлены сахар и соль. Вторая — сводку первого коммита: `pancakes.txt | 3 +++`.

### Частые ошибки

- `git diff` пустой, хотя файл изменён → изменения уже в индексе. Смотрите `git diff --staged`.
- Новый файл не виден в `git diff` → он неотслеживаемый. Сначала `git add файл`, потом `git diff --staged`.
- Файл поправлен в редакторе, а `git diff` молчит → файл не сохранён. Нажмите Ctrl+S.
- `echo "текст" > файл` вместо `>>` → файл перезаписан, остальные строки пропали. Для дописывания нужен `>>`.

### Шпаргалка

- Редактор: панель «Файлы» → щелчок по файлу → правка → Ctrl+S
- `echo "текст" >> файл` — дописать строку в конец
- `git diff` — правки, которых ещё нет в индексе
- `git diff --staged` — что войдёт в следующий коммит
- `git diff --stat`, `git diff --staged --stat` — краткая сводка
- `-` удалено, `+` добавлено, пробел — без изменений; `@@ -старт,строк +старт,строк @@` — заголовок фрагмента
- `git log -n число`, `git log --oneline -n число` — последние коммиты
- `git show`, `git show HEAD~1`, `git show коммит --stat` — изменения коммита

В репозитории `~/cafe` два файла меню: `day.txt` (меню дня) и `evening.txt` (вечернее меню). В рабочей папке изменены оба: в одном добавлен десерт, в другом поменялась цена кофе. Какой файл какой правкой затронут, выясните сами.

Сохраните правки двумя отдельными коммитами:

1. сначала файл с десертом — сообщение **Добавлен десерт**;
2. затем файл с новой ценой кофе — сообщение **Изменена цена кофе**.

```sh setup
mkdir cafe
cd cafe
git init -q
cat > day.txt <<'EOF'
Суп дня — 250
Кофе — 150
EOF
cat > evening.txt <<'EOF'
Паста — 450
Чай — 120
EOF
git add day.txt evening.txt
git commit -q -m "Меню кафе"
cat > day.txt <<'EOF'
Суп дня — 250
Кофе — 180
EOF
echo "Тирамису — 300" >> evening.txt
```

```sh solution
git add evening.txt
git commit -m "Добавлен десерт"
git add day.txt
git commit -m "Изменена цена кофе"
```
