# Игнорирование и отмена

Программа пишет журналы, сборщик складывает готовые файлы в папку `build`, а вы случайно испортили рабочий файл и добавили в индекс черновик. Если всё это попадёт в коммит, история засорится. В этом уроке вы скажете Git, какие файлы не замечать, научитесь отменять незакоммиченные правки, а также удалять и переименовывать файлы так, чтобы Git это понял.

### .gitignore — что Git не должен видеть

`.gitignore` — обычный текстовый файл в корне репозитория. Каждая его строка — шаблон имён. Файлы, которые подходят под шаблон, Git не показывает в `git status` и не добавляет командой `git add .`.

```sh
*.log
build/
```

- одна строка — один шаблон;
- `*` — любые символы, поэтому `*.log` — все файлы с окончанием `.log` в любой папке репозитория;
- имя с `/` на конце, например `build/`, — папка целиком со всем содержимым;
- строка, начинающаяся с `#`, — комментарий;
- сам `.gitignore` коммитят, как любой другой файл: тогда правила действуют у всей команды.

Имя файла начинается с точки, поэтому `ls` его не показывает. Проверить содержимое можно командой `cat .gitignore`. Создать файл удобно через `echo`: первую строку записать с `>`, остальные дописать с `>>`.

Подготовим учебный репозиторий `game` и посмотрим, как шаблоны прячут лишнее.

```sh example
cd ~
mkdir game
cd game
git init
echo "Уровень 1" > level1.txt
echo "Купить звуки" > todo.txt
echo "volume=80" > settings.ini
echo "Стрелки — движение" > help.txt
git add level1.txt todo.txt settings.ini help.txt
git commit -m "Первый уровень"
echo "временные данные" > cache.tmp
mkdir dist
echo "сборка" > dist/game.js
git status
```

В разделе `Untracked files` видны `cache.tmp` и `dist/`. Добавим правила:

```sh example
echo "*.tmp" > .gitignore
echo "dist/" >> .gitignore
git status
git add .gitignore
git commit -m "Игнорировать временные файлы"
```

После правил `git status` показывает только сам `.gitignore`: временный файл и папка сборки исчезли из вывода, хотя на диске они остались.

Важно: `.gitignore` действует только на неотслеживаемые файлы. Если файл уже был в коммите, Git продолжит следить за ним — как это исправить, рассказано в разделе про `git rm --cached`.

### git restore — отменить правку в рабочей папке

`git restore` возвращает файл к версии из индекса. Если вы не делали `git add`, в индексе лежит версия последнего коммита, то есть правка просто пропадает.

```sh
git restore файл
```

- `restore` — восстановить;
- `файл` — какой файл вернуть; можно перечислить несколько.

Отменённую правку вернуть нельзя: Git её не сохранял. Перед `git restore` загляните в `git diff файл`, чтобы убедиться, что выбрасываете именно то, что нужно.

```sh example
echo "Секретный уровень" >> level1.txt
git status
git restore level1.txt
cat level1.txt
```

После `git restore` в файле снова одна строка `Уровень 1`. Подсказку с этой командой Git печатает сам в `git status`: `use "git restore <file>..." to discard changes`.

### git restore --staged — убрать из индекса

Иногда в индекс попадает лишнее. Флаг `--staged` убирает файл из индекса, но содержимое файла в рабочей папке не трогает.

```sh
git restore --staged файл
```

- `--staged` — работать с индексом, а не с рабочей папкой;
- `файл` — что убрать из следующего коммита.

Если файл был новым, он снова станет неотслеживаемым. Если файл был изменён, правка останется в рабочей папке и переместится в раздел `Changes not staged for commit`.

```sh example
echo "Уровень 2" > level2.txt
git add level2.txt
git status
git restore --staged level2.txt
git status
```

Первый `git status` показывает `new file: level2.txt` в индексе, второй — `level2.txt` в `Untracked files`. Файл на месте.

Разница двух вариантов:

- `git restore файл` — выбросить правку из рабочей папки;
- `git restore --staged файл` — только вынуть из индекса, правка сохраняется.

### git rm — удалить файл из проекта

`git rm` удаляет файл из рабочей папки и сразу записывает удаление в индекс. Следующий коммит зафиксирует, что файла больше нет.

```sh
git rm файл
```

- `rm` — удалить (remove);
- `файл` — какой отслеживаемый файл удалить.

Обычная команда `rm файл` тоже удаляет файл с диска, но удаление не попадает в индекс: его придётся добавить отдельно через `git add файл` или `git rm файл`.

```sh example
git rm todo.txt
ls
```

Git отвечает `rm 'todo.txt'`, и в списке `ls` файла больше нет.

### git rm --cached — перестать отслеживать файл

Бывает, что в коммит уже попал файл, которому там не место: локальные настройки или пароли. Флаг `--cached` удаляет файл только из индекса, а на диске оставляет.

```sh
git rm --cached файл
```

- `--cached` — удалить только из индекса;
- `файл` — какой файл перестать отслеживать.

После коммита файл исчезнет из следующих снимков, но останется у вас в рабочей папке как неотслеживаемый. Чтобы он не мешал в `git status` и не вернулся в репозиторий через `git add .`, допишите его имя в `.gitignore`.

```sh example
git rm --cached settings.ini
ls
```

Git снова пишет `rm 'settings.ini'`, но `ls` показывает, что файл на месте.

### git mv — переименовать или переместить

`git mv` переименовывает файл и сразу записывает переименование в индекс.

```sh
git mv старое-имя новое-имя
```

- `mv` — переместить (move);
- `старое-имя` — отслеживаемый файл;
- `новое-имя` — новое имя или путь в другой папке.

В `git status` переименование видно как `renamed: старое -> новое`.

```sh example
git mv help.txt HELP.md
git status
git commit -m "Уборка в файлах"
```

В индексе три изменения: `renamed: help.txt -> HELP.md`, `deleted: settings.ini` и `deleted: todo.txt`. Ниже, в `Untracked files`, — `settings.ini`: файл остался на диске, но Git за ним больше не следит.

### Частые ошибки

- Файл добавлен в `.gitignore`, но по-прежнему виден как изменённый → он уже отслеживается. Выполните `git rm --cached файл` и сделайте коммит.
- `git restore файл`, чтобы убрать файл из индекса → правка безвозвратно потеряна. Для индекса нужен `git restore --staged файл`.
- `rm файл` вместо `git rm файл` → `git status` покажет `deleted:` в разделе `Changes not staged for commit`. Удаление нужно добавить в индекс: `git rm файл`.
- `git rm` для файла, который нужно сохранить на диске → файл удалён. Чтобы только перестать отслеживать, используйте `git rm --cached`.

### Шпаргалка

- `.gitignore`: одна строка — один шаблон; `*.log` — все файлы `.log`; `build/` — папка; `#` — комментарий
- `git restore файл` — выбросить правку из рабочей папки
- `git restore --staged файл` — убрать из индекса, правка остаётся
- `git rm файл` — удалить файл и записать удаление в индекс
- `git rm --cached файл` — перестать отслеживать, файл остаётся на диске
- `git mv старое новое` — переименовать с записью в индекс


В репозитории `~/bot` закоммичены файлы `bot.js`, `readme.txt`, `old-notes.txt` и `.env` (настройки с паролем). Наведите порядок одним коммитом:

1. переименуйте `readme.txt` в `README.md`;
2. удалите `old-notes.txt` из проекта;
3. перестаньте отслеживать `.env`, но оставьте его на диске;
4. создайте `.gitignore` из одной строки `.env` и добавьте его в индекс;
5. сделайте коммит с сообщением **Уборка в репозитории**.

```sh setup
mkdir bot
cd bot
git init -q
echo "bot.start()" > bot.js
echo "Чат-бот для заказов" > readme.txt
echo "старые идеи" > old-notes.txt
echo "DB_PASSWORD=qwerty" > .env
git add bot.js readme.txt old-notes.txt .env
git commit -q -m "Бот"
```

```sh solution
git mv readme.txt README.md
git rm old-notes.txt
git rm --cached .env
echo ".env" > .gitignore
git add .gitignore
git commit -m "Уборка в репозитории"
```
