# Тест для тех, кто работал с RabbitMQ

Девять вопросов в трёх блоках. Если в блоке правильных ответов хотя бы два, его уроки засчитываются, и вы начнёте с первой незнакомой темы. Мир «Проектирование и эксплуатация» тест не засчитывает.

```json
  ],
  "answer": [1],
```

```json
{
  "type": "choice",
  "title": "Потребитель упал до подтверждения",
  "hints": ["Неподтверждённые сообщения принадлежат каналу, который их получил."],
  "options": [
    "Три сообщения потеряны: они уже были выданы",
    "Брокер вернёт три сообщения в очередь, и их получит другой потребитель с пометкой `redelivered`",
    "Брокер повторит их тому же потребителю, как только он перезапустится, а остальным не отдаст",
    "Сообщения останутся в состоянии «неподтверждено» до ручной очистки"
  ],
  "answer": [1],
  "explanation": "При ручном подтверждении брокер считает сообщение обработанным только после `basic.ack`. Когда канал или соединение закрывается, неподтверждённые сообщения возвращаются в очередь с признаком `redelivered`, и их может взять любой потребитель. ```
```

Потребитель с ручным подтверждением получил три сообщения и упал, не отправив `basic.ack`. Что сделает брокер?

## task rmq-pl-prefetch

```json
{
  "type": "choice",
  "title": "Зачем ограничивать prefetch",
  "hints": ["Сколько неподтверждённых сообщений брокер выдаёт потребителю, пока тот занят?"],
  "options": [
    "Без ограничения брокер раздаст сообщения потребителям заранее, и медленный потребитель накопит у себя очередь, пока другой простаивает",
    "Prefetch нужен, чтобы подтверждать сообщения пачкой",
    "Prefetch шифрует сообщения при выдаче",
    "Без ограничения сообщения доставляются в случайном порядке"
  ],
  "answer": [0],
  "explanation": "`prefetch_count` ограничивает число неподтверждённых сообщений у потребителя. Если лимита нет, брокер быстро выдаёт всё подряд, и сообщения застревают у занятого потребителя, пока другой свободен. С небольшим значением новое сообщение выдаётся только после подтверждения предыдущего, поэтому нагрузка распределяется ровнее."
}
```

Два потребителя читают одну очередь, один из них заметно медленнее. Почему стоит задать небольшой prefetch?
